Einführung

ChameleonDrummer ist ein dynamisches MIDI-Schlagzeug-Erzeugungssystem, gebaut in Free Pascal (FPC) mit der Lazarus Component Library (LCL). Es erzeugt realistische Schlagzeugmuster für 5 Genres (Metal, Rock, Jazz, Funk, Electronic) mit insgesamt 32 Stilen und 17 Schlagzeuger-Persönlichkeiten. Es unterstützt mehrere MIDI-Keymaps (GM, AD2, EZD3, XG), Taktarten von 2/4 bis 32/16 (einschließlich ungerader Taktarten wie 3/4, 5/4, 7/8, 9/8, 11/8, 13/8...), externe Groove/Fill/Default-Dateien, REAPER .rpp und Ardour .ardour Session-Export, sowie erweiterte Humanisierung, Intensitätskurven und physische Spielbarkeitsbeschränkungen.

Zwei Ausführbare werden erzeugt:

  • ChameleonDrummer.exe — Kommandozeilen-Schnittstelle
  • chameleondrummer_gui.exe — grafische Schnittstelle (Lazarus/LCL)

Installation

Anforderungen

  • Windows (primäres Ziel; Linux/macOS möglich mit FPC/LCL)
  • Free Pascal Compiler (FPC) 3.2.2+
  • Lazarus IDE (optional, für grafische Oberfläche-Entwicklung)
  • Free Pascal Compiler (FPC) 3.2.2+ (für den tools/midi_to_tab.exe Konverter)

Bauen aus dem Quellcode

# Kommandozeilenprogramm-Ausführbare
cd B:\dev\github\ChameleonDrummer
"%SystemDrive%\lazarus\fpc\3.2.2\bin\x86_64-win64\fpc.exe" -O2 -Fusrc -Sg -Sc ChameleonDrummer.lpr

# grafische Oberfläche-Ausführbare
cd gui
cmd /c "build_gui.bat < NUL"

Ausführen der Ausführbaren

Beide Ausführbaren sind selbstständig. Platziere ChameleonDrummer.exe und chameleondrummer_gui.exe im selben Verzeichnis, oder referenziere das Kommandozeilenprogramm vom Arbeitsverzeichnis der grafischen Oberfläche aus.

Schnellstart

Kommandozeilenprogramm — Einen Metal-Song generieren

ChameleonDrummer.exe generate --genre metal --style death --tempo 195 --drummer hoglan --mapping ad2 --output death_metal.mid

Kommandozeilenprogramm — Einen Rock-Pattern mit Bonham-Stil generieren

ChameleonDrummer.exe pattern --genre rock --style classic --drummer bonham --output bonham_verse.mid

Kommandozeilenprogramm — In einer ungeraden Taktart generieren

ChameleonDrummer.exe generate --genre rock --style classic --time-sig 7/8 --output rock_7_8.mid

Kommandozeilenprogramm — Verfügbare Optionen auflisten

ChameleonDrummer.exe list genres
ChameleonDrummer.exe list styles --genre jazz
ChameleonDrummer.exe list drummers
ChameleonDrummer.exe list mappings

Grafische Oberfläche — Interaktive Generierung

  1. Starte chameleondrummer_gui.exe.
  2. Wähle Genre: metal.
  3. Wähle Stil: death.
  4. Wähle Schlagzeuger: hoglan.
  5. Wähle Mapping: ad2.
  6. Setze Tempo: 195.
  7. Passe Komplexität und Humanisierung Regler an.
  8. Klicke Generieren.
  9. Sieh die Ausgabe im Log-Panel.

Konzepte der MIDI-Schlagzeug-Erzeugung

Dieser Abschnitt erklärt die zugrundeliegenden Prinzipien, abgeleitet aus dem Quellcode (ComposerV2.pas, DrumGenerator.pas, Pattern.pas, Song.pas, MidiIO.pas).

1. Pattern- und Beat-Modell (Pattern.pas)

Ein TPattern ist ein Container von TBeat Objekten. Jeder Beat hat:

  • Position (Double): Zeit in Beats (z.B. 0.0, 0.5, 1.0). Position 1.0 = der zweite Beat, Position 2.0 = der dritte Beat, usw.
  • Instrument (TDrumInstrument): Das Schlagzeuginstrument (Kick, Snare, Hi-Hat, etc.). Die Instrumentenidentität kommt aus einer JSON-Keymap-Datei — keine Noten sind im Pascal-Code hardcodiert.
  • Velocity (Integer): MIDI-Velocity von 0 (stumm) bis 127 (Maximum). Das macht manche Hits lauter oder leiser.
  • Dauer (Double): Notenlänge in Beats. Die meisten Drum-Hits sind sehr kurz (~0.1 Beats), aber manche können für Effekte länger sein.
  • GhostNote (Boolean): Subtile, niedrige-Velocity-Noten für Groove-Gefühl. Denk daran als der Schlagzeuger, der leicht den Rand einer Trommel zwischen den Haupt-Hits antippt.
  • Accent (Boolean): Betonter Hit. So setzt der Schlagzeuger Akzente auf bestimmte Beats (wie die Snare auf Beats 2 und 4 im Rock).
  • InstrumentPromoted (Boolean): Herkunfts-Flag. True nur, wenn das Instrument dieses Beats von einem Genre-Plugin an Ort und Stelle geändert wurde, indem ein bestehender Hi-Hat-Beat zu einem höherenergetischen Becken für einen High-Energy-Abschnitt promoviert wurde.

2. Song- und Section-Modell (Song.pas)

Ein TSong enthält Sections (TSection), jede mit eigenen Patterns, Fills, Tempo und Taktart. Sections sind in einer Standard-Song-Reihenfolge angeordnet: Intro, Verse, Pre-Chorus, Chorus, Bridge, Breakdown, Solo, Outro.

Jede Section hat ihre eigenen:

  • Tempo — Geschwindigkeit in Beats pro Minute (BPM). 0 bedeutet Song-Tempo erben.
  • Taktart — die Taktart (4/4, 7/8, 5/4, etc.). Die erste Zahl ist die Anzahl Beats pro Takt, die zweite Notenwert bekommt einen Beat.
  • Komplexität — wie variiert die Patterns sind. Nur verwendet wenn HasComplexity gesetzt ist; null-gefüllte Records erben die Song-Komplexität.
  • Standard-Patterns — welche Grooves/Fills die Engine für diese Section wählen soll.

Sections werden in einfachen JSON-Dateien gespeichert. Du kannst eigene Sections hinzufügen, die Reihenfolge ändern, oder jeder Section ihr eigenes Tempo und ihre eigene Taktart geben.

3. Takt-für-Takt Pattern-Evolution (ComposerV2.pas)

TBarSelector.SelectPatternForPhrase wählt einen Groove für jeden Takt mittels gewichteter Zufallsziehung:

  • Intensitäts-Abgleich: Das Gewicht jedes Grooves basiert darauf, wie gut sein Intensitätsband zum Takt passt. Grooves, deren Band die Takt-Intensität enthält, bekommen einen Bonus.
  • Rezenz-Gewichtung: Das Gewicht des vorherigen Patterns wird auf 0.25× reduziert, damit es zurückkehren kann, aber selten direkt nacheinander wiederholt wird. Das verhindert, dass dasselbe Pattern Takt für Takt spielt.
  • Makro-Phasen: Der Song entwickelt sich in vier Phasen:
    • mpEstablish (frühe Takte): probiert leichtere Grooves, um das Gefühl zu setzen
    • mpMaintain (mittlere Takte): behält bei, was funktioniert
    • mpBuild (zum Höhepunkt): bevorzugt schwerere, intensivere Grooves
    • mpTurnaround (Ende): führt zurück zum Anfang oder Chorus
  • Thread-sichere Zufälligkeit: Auswahl nutzt TThreadedRandom für konsistente Ergebnisse über Threads hinweg.

4. Intensitätskurven (ComposerV2.pas)

Intensität variiert über den Song: Intro/Verse sind leichter, Chorus ist schwerer, Bridge/Breakdown variieren. Die Intensitätskurve steuert sowohl Pattern-Auswahl als auch Fill-Platzierung. Typische Kurven:

  • icAscending — wird lauter zum Höhepunkt
  • icDescending — startet laut, fadet aus
  • icPlateau — grob konstante Intensität
  • icDipRise — dips dann steigt (üblich für Verse-Chorus-Verse)
  • icSteps — deutliche Intensitätsänderungen an Section-Grenzen

5. Makro-Komponist (ComposerV2.pas)

Die Makro-Phase verzerrt die Pattern-Auswahl pro Section. Die vier Phasen (mpEstablish, mpMaintain, mpBuild, mpTurnaround) kontrollieren, wie sich der Groove über den Song entwickelt, wie ein musikalischer Direktor der sagt "fange einfach an, baue Energie auf, dann bring es nach Hause."

6. Groove-Engine (ComposerV2.pas)

Grooves werden aus config/grooves/.tab Dateien geladen. Jeder Block definiert ein Stil/Art/Intensitätsband. Die Engine wählt den am besten passenden Groove pro Takt.

Groove-Block-Format:

[style kind intensity=low-high]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.
  • Header: [style kind intensity=low-high]
  • style — z.B. metal, rock, jazz, funk, electronic
  • kind — verse, chorus oder bridge
  • intensity=low-high — die Takt-Intensitäten (0–1), die dieser Groove passt, z.B. intensity=0.20-0.60
  • Taktart nach Art hinzufügen: [classic verse 7/8 intensity=0.2-0.7] für ungerade-Meter-Grooves
  • Instrumenten-Zeilen: Eine Zeile pro Instrument. Format: INSTRUMENT SCHRITT SCHRITT SCHRITT | SCHRITT SCHRITT SCHRITT
  • K = Kick, S = Snare, RS = Ride-Becken kurz, SS = Splash, H = Hi-Hat, HO = Hi-Hat offen, HP = Hi-Hat Pedal, R = Rack Tom, RB = Bass Tom, C = Crash-Becken, C2 = zweites Crash, CH = China, SP = Splash, T1 = Tom 1, T2 = Tom 2, T3 = Tom 3, T4 = Tom 4
  • Schritt-Zeichen: . = Pause (kein Hit), x = Hit, X = akzentuierter Hit, o = weiche Note, g = Ghost-Note
  • Leerzeichen innerhalb eines Takts werden ignoriert (sie verbessern nur die Lesbarkeit)
  • Takte werden durch | getrennt. Die Engine nutzt die Taktanzahl der längsten Zeile; kürzere Zeilen wiederholen ihre Takte.
  • Beispiel (aus rock.tab):
[rock verse intensity=0.20-0.60]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.

7. Fill-System (ComposerV2.pas)

Fills werden aus config/fills/.tab geladen. Jeder Block definiert ein Name/Energie-Band. Die Engine wählt einen Fill, dessen Energie zur Takt-Intensität an Section-Grenzen passt.

Fill-Block-Format:

[bonham_fill_short energy=0.3]
S ... ... ... xxx
  • Header: [name energy=0.3]
  • name — z.B. bonham_fill_short, peart_fill_odd_7_8
  • energy=0.3 — die Takt-Intensität (0–1), die der Fill am besten passt
  • Gleiches Instrument/Schritt-Format wie Grooves: Gleiche Schritt-Zeichen (., x, X, o, g), gleiche Takt/Takt-Trenn-Regeln.

8. Humanisierung (AdvancedHumanization.pas)

Timing- und Velocity-Jitter werden pro Note angewendet, skaliert durch die Humanisierungseinstellung. Ghost-Notes und Accents werden beibehalten.

  • Timing-Jitter: Jede Note wird um wenige Millisekunden vor oder zurück verschoben. Klein genug, um natürlich zu wirken, groß genug, um den "Maschinengewehr"-Effekt zu vermeiden.
  • Velocity-Variation: Manche Hits sind etwas lauter oder leiser als erwartet.
  • Swing: Ein Gefühl, bei dem gerade Achtelnoten mit einem leichten 2:1 oder 3:1 Verhältnis gespielt werden, wie ein klassischer Rock- oder Funk-Groove. Gesteuert durch die --swing Kommandozeilenprogramm-Flag oder grafische Oberfläche-Regler (0 = gerade, 0.67 = klassisch 2:1, 1 = 3:1).

Du steuerst all das mit dem Humanisierung Regler in der grafischen Oberfläche (0–1). Bei 0 ist es perfekt auf dem Grid. Bei 1 hat es maximales Gefühl.

9. Physische Beschränkungen (PhysicalConstraints.pas / PatternFixer.pas)

Der Pattern-Fixer entfernt unmögliche Hits:

  • Maximal 3 Hits auf einem Schritt: Ein Schlagzeuger kann nicht Kick, Snare und zwei Toms gleichzeitig in einer Bewegung treffen.
  • Glieder-Koordinationsmuster:
    • Rechte Hand: spielt typischerweise Crash- oder Ride-Becken
    • Linke Hand: Hi-Hat oder Ride-Becken
    • Rechter Fuß: Kick-Pedal
    • Linker Fuß: Hi-Hat-Pedal
  • Das verhindert, dass die Engine Patterns erzeugt, die ein echter Schlagzeuger nicht physisch spielen könnte.

10. Plugin-Architektur (PluginRegistry.pas, DrumGenerator.pas)

Genre-Plugins und Schlagzeuger-Plugins werden in das Executable kompiliert. Jeder Schlagzeuger wendet 2–4 Modifikationen an:

  • BehindBeat: Der Schlagzeuger spielt leicht hinter dem Beat für ein entspanntes Gefühl.
  • GhostNotes: Fügt subtile Rim-Shots und leise Noten hinzu.
  • LinearCoordination: Typische Gliedermuster für diesen Schlagzeuger (z.B. Bonhams charakteristische Kick-Snare-Patterns).
  • ShuffleFeel: Swing-Gefühl spezifisch für diesen Stil.
  • FillPatterns: Typisches Fill-Vokabular für diesen Schlagzeuger.

Modifikationen sind komponierbar und werden in Reihenfolge angewendet. Genre-Plugins (Metal, Rock, Jazz, Funk, Electronic) definieren die typischen Intensitätsbänder, welche Grooves für diesen Stil Sinn machen, und die Standard-Song-Struktur.

11. Keymap-System (Kit.pas)

MIDI-Noten werden durch JSON-Keymap-Dateien in mappings/ aufgelöst. Keine hardcodierten Noten existieren im Pascal-Code.

  • Keymap-Dateien mappen Notennamen (kick, snare, hi-hat, tom1, crash, etc.) auf MIDI-Noten.
  • Die gleiche Generierungs-Engine kann jede Keymap nutzen — GM, AD2, EZDrummer 3, Yamaha XG, oder benutzerdefinierte.
  • Du kannst Keymap-JSON-Dateien bearbeiten, um anzupassen, welche Note welches Drum triggert.

    • Deshalb funktioniert das System mit so vielen verschiedenen Drum-Libraries und warum die grafische Oberfläche keine Drum-Namen hardcodiert.

12. MIDI-Export (MidiIO.pas, MidiParser.pas)

Rohes SMF Format 0 mit VLQ-Kodierung, Tempo/Taktart-Meta-Events, kompatibel mit allen DAWs und Drum-VSTs.

  • Tracks: Ein MIDI-Track mit allen Drum-Noten.
  • Tempo-Events: BPM-Änderungen während der Song fortschreitet.
  • Taktart-Events: Taktart-Änderungen.
  • Noten-Daten: Tonhöhe (welches Drum), Velocity, Startzeit, Dauer.

Diese MIDI-Datei funktioniert mit jeder DAW (Reaper, Ardour, Ableton, Logic, etc.) und jedem Drum-VST-Plugin (EZDrummer, Superior Drummer, Addictive Drums, etc.).

Das Programm mit grafischer Oberfläche

Das Programm mit grafischer Oberfläche (chameleondrummer_gui.exe) verlinkt die Engine direkt — es erzeugt genau das, was das Kommandozeilen-Tool erzeugt, ohne es aufzurufen.

  1. Starte chameleondrummer_gui.exe.
  2. Wähle Genre, Stil, Schlagzeuger, Keymap, Tempo, Komplexität und Humanisierung aus der Oberfläche.
  3. Klicke Generieren — eine MIDI-Datei wird geschrieben.
  4. Optional exportiere ein REAPER-Projekt (.rpp) oder eine Ardour-Session (.ardour) daneben.
  5. Dark Mode ist verfügbar über Ansicht > System/Hell/Dunkel und bleibt in gui.ini erhalten.

Das Programm mit grafischer Oberfläche bietet interaktiven Zugriff auf alle Kommandozeilenprogramm-Generierungsoptionen plus visuelles Feedback:

  • Echtzeit-Vorschau der gewählten Genre/Stil/Schlagzeuger-Kombinationen
  • Dynamische Section-Steuerelemente, die zur Laufzeit basierend auf Genre-Standards hinzugefügt werden
  • Dark Mode Unterstützung (nur für Windows kompiliert)
  • Konfigurations-Persistenz via gui.ini

Siehe gui/README.md für Details zum Lazarus Form-Layout, Komponenten-Setup und Dark Mode Implementierung.

Das Programm mit grafischer Oberfläche enthält auch einen Step Editor Button, der die eigenständige Step Editor Applikation (tools/step_editor/step_editor.exe) öffnet. Der Step Editor lässt dich Drum-Patterns visuell auf einem Step-Grid bearbeiten, MIDI-Dateien in Tab-Format konvertieren, und Patterns als Grooves oder Fills speichern. Siehe Step Editor für Details.

REAPER-Integration

ChameleonDrummer integriert sich mit REAPER über ein Lua-Panel (reaper_chameleon/chameleon_panel.lua), das das Kommandozeilenprogramm für Drum-Generierung antreibt und Ergebnisse direkt in dein REAPER-Projekt importiert.

Installation

  1. Kopiere das reaper_chameleon/ Verzeichnis in deinen REAPER Scripts-Ordner.
  2. Öffne REAPER und lade chameleon_panel.lua über Actions > Show action list > New > ReaScript.
  3. Das Panel erscheint als andockbares Fenster mit vier Tabs.

Tabs

Song Sections

  • Wähle Genre, Stil, Schlagzeuger, Mapping, Tempo, und Anzahl Takte
  • Generiere MIDI via Kommandozeilenprogramm und importiere in das aktuelle REAPER-Projekt
  • Exportiere REAPER-Projekt (.rpp) neben der MIDI

Additive Rhythm

  • Gib additive Gruppierungsnotation ein (z.B. 3-3-3-3-2-2)
  • Setze Grid-Auflösung (4, 8, 16, 32), Tempo, Schlagzeuger, Intensität
  • Generiere additive Rhythmus-Patterns mit pro-Takt Taktarten
  • Optionaler Timeline JSON Export für REAPER Tempo-Marker

Step Editor

  • Lade ein MIDI-Item aus dem aktuellen Projekt
  • Bearbeite auf einem Grid mit Schlagzeuger-Anwendung (Timing/Velocity-Varianz)
  • Wende Schlagzeuger-Stil auf existierende Patterns an

Settings

  • Konfiguriere Kommandozeilenprogramm-Ausführbaren-Pfad
  • Setze Standard Genre/Stil/Schlagzeuger/Mapping
  • Aktualisiere Optionen von Kommandozeilenprogramm list Befehlen

Log

  • Echtzeit-Log-Ausgabe von Kommandozeilenprogramm-Befehlen
  • Status-Meldungen während der Generierung

Kommandozeilenprogramm-Befehle, die vom REAPER Panel genutzt werden

Das Kommandozeilenprogramm

Befehlsreferenz

Usage: chameleondrummer  [options]

Commands:
  generate         Generate a complete song (multi-bar pattern)
  pattern          Generate a single 1-4 bar pattern
  list             List available genres, styles, drummers, or mappings
  info             Show system information
  reaper           Create a REAPER project (sub-command: export)
  ardour           Create an Ardour session (sub-command: export)
  additive-rhythm  Generate additive rhythm patterns

Options:
  --genre               Genre (metal, rock, jazz, funk, electronic)
  --style               Style within genre (heavy, classic, swing, ...)
  --tempo                Tempo in BPM (default: genre/style value)
  --complexity <0-1>          Pattern complexity (default: 0.5)
  --humanization <0-1>        Humanization intensity (default: 0.3)
  --swing <0-1>               Swing feel: 0 = straight (default), 0.67 = classic 2:1, 1 = 3:1
  --time-sig             Meter of the song, e.g. 3/4, 5/4, 7/8, 9/8, 11/8, 13/8 (default 4/4)
  --strict-meter              Only use patterns matching --time-sig
  --segment   A section with its own tempo and meter, e.g. bridge:4:96:7/8
                              (bpm - keeps the song tempo); mix freely with --section
  --section     Song structure; repeat once per section, in order
                              e.g. --section intro:4 --section verse:8 --section chorus:8@140
                              (without --section the genre default structure is used)
  --drummer             Drummer style (e.g., bonham, peart, carey)
  --output              Output MIDI file path
  --reaper, --ardour          With generate: also write .rpp / the .ardour session
  --mapping             Keymap to use: gm (default), ad2, ezd3, xg
  --structure           Song structure from a JSON file (sections with bars, tempo,
                              complexity; optional genre, style, tempo). Command-line
                              genre/style/tempo win over the file. Not with --section.
  --sidecar             Same as --structure (the REAPER sidecar format works)
  --song-map            Read song map JSON for per-bar tempo/meter
  --write-timeline            Write timeline JSON after generation
  --list                List: genres, styles, drummers, mappings
  --json                      Output JSON for list commands
  --grouping             Additive grouping notation (e.g., 3-3-3-3-2-2)
  --grid                   Grid resolution for additive-rhythm (4, 8, 16, 32)
  --drummer-intensity <0-1>   Drummer intensity for additive-rhythm
  --help, -h                  Show this help

Beispiele

Einen vollständigen Song generieren:

ChameleonDrummer.exe generate --genre metal --style death --tempo 195 --drummer hoglan --mapping ad2 --output death_metal.mid

Einen einzelnen Pattern generieren:

ChameleonDrummer.exe pattern --genre jazz --style swing --output swing_verse.mid

REAPER-Projekt erstellen:

ChameleonDrummer.exe reaper export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.rpp

Ardour-Session erstellen:

ChameleonDrummer.exe ardour export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.ardour

Additive Rhythmus-Pattern:

ChameleonDrummer.exe additive-rhythm --grouping "3-3-3-3-2-2" --grid 16 --tempo 120 --mapping gm --drummer bonham --drummer-intensity 0.8 --output additive.mid

Erweiterte Funktionen

Song Maps und Sidecars

Sections (--section): Beschreibt die Song-Struktur direkt auf der Kommandozeile, ein --section pro Section, in Spielreihenfolge:

ChameleonDrummer.exe generate --genre metal --style death --section intro:4 --section verse:8 --section chorus:8 --section bridge:4 --output song.mid

Sidecar (--sidecar): Eine JSON-Datei, die Sections mit Takten, Tempo, Komplexität, und optionalen Genre/Stil/Tempo-Overrides beschreibt. Die Kommandozeilen-Genre/Stil/Tempo gewinnen über die Datei.

Song Map (--song-map): Eine JSON-Datei, die pro-Takt Tempo- und Taktart-Änderungen für komplexe progressive Songs beschreibt.

Ungerade Taktarten

Die Engine unterstützt Taktarten von 2/4 bis 32/16. Nutze --time-sig n/d oder --segment um sie anzugeben. Grooves und Fills werden aus .tab Dateien geladen, die ihre Taktart im Block-Header deklarieren (z.B. [metal verse 7/8 intensity=0.40-0.90]).

Eigene Grooves, Fills und Defaults

Bearbeite Dateien in config/:

  • config/grooves/.tab — neue Grooves hinzufügen, Intensitätsbänder ändern
  • config/fills/.tab — neue Fills hinzufügen, Energie-Level ändern
  • config/defaults/.ini — Standard Tempo/Stil/Schlagzeuger ändern
  • config/sections/.json — Standard Song-Struktur ändern

Keine Neukompilierung nötig — die Engine liest diese zur Laufzeit.

Lookup-Reihenfolge

  1. Der Ordner in der Umgebungsvariable CHAMELEON_CONFIG, falls gesetzt
  2. %APPDATA%\ChameleonDrummer\config (Linux: ~/.config/ChameleonDrummer/config)
  3. config neben dem Programm
  4. ..\config (Entwicklungs-Builds)

MIDI → Tab-Konvertierung

tools/midi_to_tab.exe konvertiert eine MIDI-Datei in das .tab Groove/Fill-Format. Aus Pascal kompiliert, keine externen Abhängigkeiten.

midi_to_tab.exe input.mid [output.tab]
midi_to_tab.exe input.mid --fill --name bonham_fill --energy 0.6
midi_to_tab.exe input.mid --meter 7/8 --resolution 16
midi_to_tab.exe input.mid --mapping mappings/gm.json --style rock --kind verse

Optionen

OptionBeschreibung
--fillEinen Fill-Block statt Groove-Block ausgeben
--name Fill-Name (Standard: fill)
--energy <0-1>Fill-Energie (Standard: 0.5)
--meter Taktart-Override (Standard: aus MIDI Meta oder 4/4)
--resolution Schritte pro Viertelnote: 4, 8, 16, 32 (Standard: 16)
--mapping Keymap JSON Datei (Standard: eingebaute GM Map)
--style Groove Stil-Name (Standard: midi)
--kind Groove Art: verse/chorus/bridge (Standard: verse)
--intensity Groove Intensitätsband (Standard: 0.2-0.6)

Ausgabe wird mit CRLF Zeilenenden geschrieben, bereit für config/grooves/ oder config/fills/.

Step Editor

Der Step Editor (tools/step_editor/step_editor.exe) ist eine eigenständige grafische Applikation zum visuellen Bearbeiten von Drum-Patterns auf einem Step-Grid, Konvertieren von MIDI-Dateien in das .tab Groove/Fill-Format, und Verwalten von Pattern-Blöcken in den Config-Dateien. Er kann vom Haupt-grafische Oberfläche über den Step Editor Button gestartet werden, oder direkt ausgeführt werden.

Step Editor starten

  • Vom Programm mit grafischer Oberfläche: Klicke den Step Editor Button in der Hauptfenster-Toolbar.
  • Direkt: Führe tools/step_editor/step_editor.exe vom Projekt-Root oder Installationsverzeichnis aus.
  • Von REAPER/Ardour Panels: Der Step Editor Tab in den DAW-Integration-Panels startet den Editor mit dem aktuellen MIDI-Item geladen.

Hauptfunktionen

  • Step Grid Bearbeitung: Visuelles Grid mit 17 Drum-Instrumenten (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4) und konfigurierbaren Schritten pro Takt (4, 8, 16, 32, 64).
  • Velocity/Artikulations-Zeichen: Jeder Schritt nutzt ein Zeichen: . (Pause), x (normal), X (Accent), o (weich/ghost), g (ghost). Klicke Zellen um durch Zustände zu zyklen.
  • MIDI → Tab Konvertierung: Lade eine MIDI-Datei (.mid, .midi) und konvertiere sie in Tab-Format mittels eingebautem midi_to_tab.exe mit konfigurierbarem Mapping, Stil, Art, Intensität, Energie, Auflösung, und Taktart.
  • Tab Datei Laden: Lade existierende .tab Dateien (sowohl ChameleonDrummer Config-Format als auch fremde Tab-Formate) zum Bearbeiten.
  • Block-Navigation (Config-Dateien): Beim Laden einer Config-Datei aus config/grooves/ oder config/fills/ parst der Editor alle Pattern-Blöcke und bietet einen Dropdown-Selektor mit Prev/Next Buttons zur Navigation zwischen Blöcken.
  • Block-Bearbeitung: Bearbeite Block-Header-Felder (Stil, Art, Intensität Low/High) direkt in der UI. Änderungen werden mit einem * Indikator markiert.
  • Chirurgisches Speichern: Speichere einzelne Blöcke zurück in ihre Quelldatei ohne andere Blöcke in derselben Datei zu beeinflussen.
  • Neue/Lösche Blöcke: Füge neue leere Pattern-Blöcke hinzu oder lösche existierende (mit Bestätigung).
  • Zoom/Auflösung: Ändere Grid-Auflösung (8, 16, 32, 64 Schritte pro Takt) und Seitengröße.
  • Dark Mode: Automatische System-Theme-Erkennung (Windows) mit manuellem Override. Alle Controls inklusive Grid, Combo-Boxen, und Statusleiste sind themed.
  • Auto-Scaling: Proportionale vektorielle Skalierung aller UI-Elemente für High-DPI Displays.
  • Export: Speichere bearbeitete Patterns als neue Groove oder Fill .tab Dateien in den Config-Verzeichnissen.

MIDI → Tab Konvertierung

Wenn du eine MIDI-Datei (.mid, .midi) auswählst, führt der Editor automatisch midi_to_tab.exe mit den aktuellen UI-Einstellungen aus und zeigt das Ergebnis im Grid.

Konvertierungs-Parameter (aus UI):

  • Mapping: Keymap JSON Datei (Standard: eingebaute GM).
  • Style: Groove Stil-Name (z.B. metal, rock, jazz).
  • Kind: Groove Art (verse, chorus, bridge, intro, outro, fill).
  • Intensity: Band für Grooves (z.B. 0.2-0.6).
  • Energy: Level für Fills (0.1–1.0).
  • Resolution: Schritte pro Viertelnote (4, 8, 16, 32).
  • Meter: Taktart (z.B. 4/4, 7/8, 4/4T für Triolen-Feeling).
  • Fill Mode: Wenn aktiviert, gibt einen Fill-Block statt Groove-Block aus.

Die rohe Konvertierungs-Ausgabe wird im Status-Log für Debugging angezeigt.

Tab Dateiformate

Der Editor handhabt zwei Tab-Dateiformate:

1. ChameleonDrummer Config Format (config/grooves/*.tab, config/fills/*.tab)

Mehrere Pattern-Blöcke in einer Datei, jeder mit einem Header:

[metal verse intensity=0.20-0.60]
K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...
|
K   x.x.x.x.x.x.x.x
...

[metal chorus intensity=0.40-0.80]
K   x.x.x.x.x.x.x.x
...

Beim Laden einer Config-Datei:

  • Parst alle Blöcke und füllt den Block-Selektor-Dropdown.
  • Zeigt Block-Navigation UI (Selektor, Prev/Next, editierbare Header-Felder).
  • Erlaubt chirurgisches Speichern einzelner Blöcke ohne die gesamte Datei neu zu schreiben.

2. Fremdes Tab Format (einzelnes Pattern, keine Block-Header)

Einfaches Format mit nur Instrumenten-Zeilen:

K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...

Diese werden als einzelnes editierbares Pattern ohne Block-Navigation geladen.

Step Grid Bearbeitung

  • Klicke eine Zelle zum Zyklen: . → x → X → o → g → .
  • Bereichsauswahl: Ziehe um mehrere Zellen auszuwählen. Nutze Save Pattern As um nur den ausgewählten Bereich zu exportieren.
  • Instrumenten-Abkürzungen: Feste linke Spalte (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4).
  • Schritt-Nummern: Obere Reihe zeigt Schritt-Index innerhalb jedes Takts.
  • Takt-Trenner: Dickere vertikale Linien markieren Taktgrenzen.
  • Seiten: Nutze Prev/Next Page Buttons oder das Zoom-Dropdown um große Patterns zu navigieren.

Block Management (Nur Config-Dateien)

Wenn eine Config-Datei geladen ist:

  • Block Selektor: Dropdown zeigt alle Blöcke im Format Style Kind (IntensityLow-IntensityHigh). Modifizierte Blöcke zeigen ein * Suffix.
  • Prev/Next: Navigiere zwischen Blöcken.
  • Header Felder: Bearbeite Style, Kind, Intensity Low, Intensity High direkt. Änderungen markieren den Block als modifiziert.
  • Save Block: Schreibt nur den aktuellen Block zurück in seine Quelldatei (chirurgisches Speichern).
  • New Block: Hängt einen neuen leeren Block (mit aktueller Meter/Auflösung) an die Datei an.
  • Delete Block: Entfernt den aktuellen Block aus der Datei (erfordert Bestätigung, behält mindestens einen Block).
