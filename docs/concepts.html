HOW CHAMELEONDRUMMER CREATES YOUR DRUM TRACKS

From ComposerV2.pas, Pattern.pas, Song.pas, and MidiIO.pas — the source code reveals a structured pipeline that any musician can understand.

  1. Pattern Model — Beats with position, instrument, velocity, ghost/accent flags.
  2. Song Structure — Sections with patterns, fills, segments, and groove offsets.
  3. Bar-by-Bar Evolution — Weighted random pattern selection with intensity bands, macro phases, context-aware fills.
  4. Physical Constraints — Pattern fixer removes impossible hits.
  5. Humanization — Timing and velocity variance for realism.
  6. MIDI Export — VLQ-encoded events with BPM/PPQ metadata.

THE ENGINE IN PLAIN LANGUAGE

ChameleonDrummer builds drum tracks like a musical director working with a session band. It picks patterns for each bar based on intensity, avoids repetition, inserts fills at section boundaries, and applies drummer-specific style modifications — all from plain text files you can edit.

Pattern Format (What You Can Edit)

Grooves and fills live in config/grooves/<genre>.tab and config/fills/<drummer>.tab. Each block has a header declaring style, meter, and intensity, followed by instrument lines using simple characters:

  • . = rest (no hit)
  • x = hit
  • X = accented hit
  • o = soft note
  • g = ghost note
  • | = bar separator

Example groove block from rock.tab:

[rock verse intensity=0.20-0.60]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.

How the Engine Works

For each bar, the engine selects a groove using weighted randomness based on intensity matching. Four macro phases (establish, maintain, build, turnaround) control how the song evolves. Fills are inserted at structural points. Humanization adds timing and velocity variation. Physical constraints prevent impossible patterns.
