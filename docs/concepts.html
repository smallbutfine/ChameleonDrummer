How ChameleonDrummer Generates MIDI Drum Patterns

This document explains the underlying concepts and architecture of the MIDI generation pipeline, derived from the Pascal source code in ChameleonDrummer/src/.

1. The Pattern Model (Pattern.pas)

A drum pattern is represented as a TPattern object containing a list of TBeat objects. Each beat encodes:

  • Position — Time in beats (e.g., 0.0, 0.5, 1.0, 1.5). Fractional positions allow subdivision beyond quarter notes.
  • Instrument — A TDrumInstrument from the instrument registry (kick, snare, hi-hat, tom, cymbal, etc.). All note mappings are loaded dynamically from JSON keymap files.
  • Velocity — MIDI velocity 0–127. Higher values = harder hits.
  • Duration — Note length in beats (default 0.25 = sixteenth note).
  • GhostNote — When true, indicates a subtle, low-velocity ghost note for groove feel.
  • Accent — When true, indicates an emphasized hit.
  • InstrumentPromoted — Provenance flag: true when a genre plugin promotes an existing hi-hat beat to a higher-energy cymbal for high-energy sections.

The TPattern also holds:

  • TimeSignature — Numerator/denominator (default 4/4).
  • Subdivision — Grid resolution (default 16 = sixteenth-note grid).
  • SwingRatio — Swing feel (0.0 = straight, >0 = swung).
  • Metadata — Key-value tags like bars_to_fill, phrase_bars.

2. Song and Section Model (Song.pas)

A complete song is a TSong object containing a list of TSection objects. Each section represents a musical part: verse, chorus, bridge, intro, outro, breakdown.

A TSection contains:

  • Name — Section identifier.
  • Pattern — The base drum pattern for this section.
  • Bars — Duration in bars.
  • Variations — List of TPatternVariation objects for variation selection per phrase.
  • Fills — List of TFill objects for fill placement.
  • Segments — TSongSegment objects allowing mid-section tempo or time-signature changes.
  • GrooveOffsetsMs — Per-bar microtiming offsets (in milliseconds) from the groove engine.

A TSongSegment allows a section to contain a mid-section tempo or meter change. This mirrors the song_creator REAPER tool's region-segment shape: {bars, bpm, num, denom}. A tempo of -1 means "inherit the parent song's global value."

3. Bar-by-Bar Evolution (ComposerV2.pas)

The core of the system is TComposerV2, which implements Engine V2: full per-bar pattern generation with intensity curves, groove selection, drummer style application, and context-aware fills.

The pipeline for each bar:

  1. Intensity Point — Calculate intensity based on the section's intensity curve (icAscending, icDescending, icPlateau, icDipRise, icSteps).
  2. Macro Phase — Determine the macro-composer phase (mpEstablish, mpMaintain, mpBuild, mpTurnaround). This ensures the song has a purposeful shape (establish → maintain → build → turnaround) rather than random picks per phrase.
  3. Groove Selection — Select a groove from the genre plugin's flavor library based on the macro phase.
  4. Drummer Style — Apply drummer modifications (behind-beat timing, triplet vocabulary, ghost notes, heavy accents, etc.).
  5. Bar Extraction — Extract the current bar from the multi-bar phrase pattern.
  6. Parameter Modulation — Apply velocity bias and dynamics scaling based on intensity and complexity.
  7. Physical Constraints — Remove hits that are physically impossible (no two hits on same hand simultaneously, max 3 simultaneous hits, no impossibly fast repeats).
  8. Humanization — Apply timing and velocity variations for realism.
  9. Fill Placement — Insert fills at musical boundaries (before section end, every 4 bars, midpoint, or random 30% chance).
  10. Combine Bars — Combine all generated bars into the final section pattern.

4. Intensity Curves

Each section is assigned an intensity curve based on its musical context:

  • icAscending — Intro sections (build up energy).
  • icDescending — Outro sections (wind down).
  • icPlateau — Chorus sections (maintain energy).
  • icDipRise — Bridge sections (dip then rise).
  • icSteps — Step-wise intensity changes.

The intensity point (IntensityPt) is a value between 0.0 and 1.0 that drives velocity bias, dynamics scaling, and groove selection.

5. Macro Composer

The TMacroComposer manages groove library phase cycling:

  • mpEstablish (first 25%): Always the first groove flavor — the opening of a section states the groove plainly.
  • mpMaintain (middle 50%): Rotates through the library without repeating the previous groove.
  • mpBuild (75–95%): Pushes toward the densest groove in the library.
  • mpTurnaround (last 5%): Random selection for transition.

6. Groove Engine

The TGrooveEngine calculates microtiming offsets per bar:

  • Drummer Bias — Per-drummer timing offset (e.g., Bonham = +25ms behind beat, Porcaro = -10ms ahead, Weckl = +5ms, Chambers = -5ms, Carey = +15ms, Hoglan = -2ms, Copeland = +20ms).
  • Section Context — Per-section adjustments (intro = -15ms, chorus = +10ms, breakdown = +5ms, bridge = -20ms).
  • Intensity Modulation — Intensity-based modulation of the offset.

Offsets are bounded to ±25ms and converted from fractional beat values to milliseconds at the given tempo.

7. Fill System

The TFillPicker determines fill placement and type:

  • Fills are placed at natural musical boundaries: ABars - 2 (before section end), every 4 bars, midpoint, or with 30% random probability.
  • Fill types: tom_downfill, tom_upfill, blast_beat, ride_bell_sweep, snare_roll, cymbal_crash.
  • Signature fills from drummer plugins are added when a drummer is specified.

8. Humanization

The TAdvancedHumanizer applies context-aware timing and velocity variations:

  • Timing Variance — Small random offsets to beat positions (simulates human imperfection).
  • Velocity Variance — Small adjustments to velocities (simulates dynamic playing).
  • Context parameters: genre, style, section, complexity, intensity, tempo, and source random seed.

9. Physical Constraints

The TPatternFixer ensures patterns are physically playable:

  • No two hits on the same hand at the same instant.
  • Maximum 3 simultaneous hits.
  • No impossibly fast repeats on one limb.
  • Removes or adjusts hits that violate these rules.

10. Plugin Architecture

The system uses a plugin registry pattern:

  • TPluginRegistry — Stores genre and drummer plugins in dictionaries keyed by lowercase name.
  • TPluginManager — Manages plugin discovery and loading from the src/ directory.
  • Genre Plugins — Provide supported styles, pattern generation methods per section, common fills, and preferred drummers.
  • Drummer Plugins — Provide compatible genres, style application (modifies patterns with drummer-specific techniques), and signature fills.

11. Keymap System

The TDrumKit class loads MIDI note mappings from JSON files in midi_drums/mappings/:

  • gm — General MIDI mapping.
  • ad2 — Addictive Drums 2 mapping.
  • ezd3 — EZDrummer 3 mapping.
  • xg — XG Standard mapping.

All instrument names and MIDI notes are data-driven. No instrument names are hardcoded.

12. MIDI Export

The MidiIO.pas unit writes standard MIDI files with:

  • Variable Length Quantity (VLQ) encoding for delta ticks.
  • Proper byte ordering (little-endian for MIDI headers).
  • Note events with absolute time basis.
  • BPM and PPQ (pulses per quarter note) metadata.

13. REAPER and Ardour Integration

The reaper/create_song_sections.lua script provides bi-directional integration between REAPER and the Python/midi_drums module. It has four modes:

  • REAPER Mode — Reads REAPER_SECTIONS table and writes midi_drums_sections.json sidecar.
  • Python Sidecar Mode — Reads existing sidecar JSON.
  • AI Agent Mode — Uses AI to choose song structure.
  • Song Map Mode — Reads song map JSON for per-bar tempo/meter.

The script calls Python via io.popen()

14. Summary: The Generation Pipeline

Putting it all together, the generation pipeline flows:

Genre Plugin → Section Flavors → GMD Pattern Library → Bar Selection →
Drummer Style → Groove Engine → Intensity Modulation → Physical Constraints →
Humanization → Fill Placement → Combine Bars → Section Assembly →
Groove Offsets → Song Assembly → MIDI Export

Each stage adds a layer of musicality and realism, from the base pattern selection to the final humanized, physically-constrained MIDI output.
