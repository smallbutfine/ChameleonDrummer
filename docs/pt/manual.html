Introdução

ChameleonDrummer é um sistema de geração dinâmica de MIDI para bateria, construído em Free Pascal (FPC) com a Lazarus Component Library (LCL). Gera padrões de bateria realistas para 5 gêneros (Metal, Rock, Jazz, Funk, Electronic) com 32 estilos no total, e 17 personalidades de bateristas. Suporta múltiplos keymaps MIDI (GM, AD2, EZD3, XG), compassos de 2/4 a 32/16 (incluindo compassos ímpares como 3/4, 5/4, 7/8, 9/8, 11/8, 13/8...), arquivos externos de grooves/fills/defaults, exportação de sessões REAPER .rpp e Ardour .ardour, e humanização avançada, curvas de intensidade, e restrições de jogabilidade física.

Dois executáveis são produzidos:

  • ChameleonDrummer.exe — interface de linha de comando
  • chameleondrummer_gui.exe — interface gráfica (Lazarus/LCL)

Instalação

Requisitos

  • Windows (alvo principal; Linux/macOS possível com FPC/LCL)
  • Free Pascal Compiler (FPC) 3.2.2+
  • Lazarus IDE (opcional, para desenvolvimento de interface gráfica)
  • Free Pascal Compiler (FPC) 3.2.2+ (para o conversor tools/midi_to_tab.exe)

Compilação da Fonte

# Executável interface de linha de comando
cd B:\dev\github\ChameleonDrummer
"%SystemDrive%\lazarus\fpc\3.2.2\bin\x86_64-win64\fpc.exe" -O2 -Fusrc -Sg -Sc ChameleonDrummer.lpr

# Executável interface gráfica
cd gui
cmd /c "build_gui.bat < NUL"

Execução do Executável

Ambos executáveis são autônomos. Coloque ChameleonDrummer.exe e chameleondrummer_gui.exe no mesmo diretório, ou referencie a interface de linha de comando do diretório de trabalho da interface gráfica.

Conceitos de Geração MIDI Bateria

Esta seção explica princípios subjacentes derivados do código fonte (ComposerV2.pas, DrumGenerator.pas, Pattern.pas, Song.pas, MidiIO.pas).

1. Modelo Padrão e Pulso (Pattern.pas)

Um TPattern é contêiner de objetos TBeat. Cada pulso tem:

  • Posição (Double): Tempo em pulsos (ex. 0.0, 0.5, 1.0). Posição 1.0 = segundo pulso, posição 2.0 = terceiro pulso, etc.
  • Instrumento (TDrumInstrument): Instrumento de bateria (bumbo, caixa, hi-hat, etc.). Identidade do instrumento vem de arquivo JSON keymap — nenhuma nota hardcodada no código Pascal.
  • Velocity (Integer): Velocity MIDI 0 (silêncio) a 127 (máximo). Faz alguns golpes soarem mais fortes ou suaves.
  • Duração (Double): Comprimento nota em pulsos. Maioria golpes bateria muito curtos (~0.1 pulsos), mas alguns podem ser mais longos para efeito.
  • GhostNote (Boolean): Nota sutil, baixa velocity para sensação groove. Pense no baterista tocando levemente aro de tambor entre golpes principais.
  • Accent (Boolean): Golpe enfatizado. Como baterista põe ênfase em certos pulsos (como caixa nos tempos 2 e 4 no rock).
  • InstrumentPromoted (Boolean): Flag proveniência. Verdadeiro só quando instrumento deste pulso alterado no local por plugin gênero promovendo golpe hi-hat existente a prato maior energia para seção alta energia.

2. Modelo Música e Seção (Song.pas)

Um TSong contém seções (TSection), cada com próprios patterns, fills, tempo, compasso. Seções ordem padrão: intro, verse, pre_chorus, chorus, bridge, breakdown, solo, outro.

Cada seção tem seus:

  • Tempo — velocidade em pulsos por minuto (BPM). 0 = herdar tempo música.
  • Compasso — assinatura tempo (4/4, 7/8, 5/4, etc.). Primeiro número = pulsos por compasso, segundo = valor nota recebe um pulso.
  • Complexidade — quão variados patterns. Só usado se HasComplexity definido; registros zerados herdam complexidade música.
  • Patterns padrão — quais grooves/fills motor deve escolher para esta seção.

Seções armazenadas em arquivos JSON simples. Pode adicionar próprias seções, mudar ordem, ou dar cada seção seu próprio tempo e compasso.

3. Evolução Padrão Compasso por Compasso (ComposerV2.pas)

TBarSelector.SelectPatternForPhrase escolhe groove cada compasso via sorteio aleatório ponderado:

  • Correspondência intensidade: Peso cada groove baseado em quão bem sua banda intensidade encaixa intensidade compasso. Grooves cuja banda contém intensidade compasso ganham bônus.
  • Ponderação recência: Peso pattern anterior reduzido a 0.25× para retorno possível mas rara repetição consecutiva. Evita mesmo pattern compasso após compasso.
  • Fases macro: Música evolui em quatro fases:
    • mpEstablish (compassos iniciais): testa grooves leves estabelecer feeling
    • mpMaintain (compassos médios): mantém o que funciona
    • mpBuild (rumo ao clímax): favorece grooves mais pesados, intensos
    • mpTurnaround (final): leva de volta ao início ou chorus
  • Aleatoriedade thread-safe: Seleção usa TThreadedRandom resultados consistentes entre threads.

4. Curvas de Intensidade (ComposerV2.pas)

Intensidade varia na música: intro/verse mais leves, chorus mais pesado, bridge/breakdown variam. Curva intensidade impulsiona seleção pattern e colocação fills. Curvas típicas:

  • icAscending — ficando mais alto rumo ao clímax
  • icDescending — começando alto, desvanecendo
  • icPlateau — intensidade ~constante
  • icDipRise — cai depois sobe (comum verse-chorus-verse)
  • icSteps — mudanças intensidade distintas nos limites seção

5. Macro Compositor (ComposerV2.pas)

Fase macro enviesa seleção pattern por seção. Quatro fases (mpEstablish, mpMaintain, mpBuild, mpTurnaround) controlam como groove evolui na música, como diretor musical dizendo "comece simples, construa energia, então traga para casa."

6. Motor Groove (ComposerV2.pas)

Grooves carregados de arquivos config/grooves/.tab. Cada bloco define estilo/tipo/banda intensidade. Motor escolhe melhor groove por compasso.

Formato bloco groove:

[style kind intensity=low-high]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.
  • Header: [style kind intensity=low-high]
  • style — ex. metal, rock, jazz, funk, electronic
  • kind — verse, chorus ou bridge
  • intensity=low-high — intensidades compasso (0–1) que groove encaixa, ex. intensity=0.20-0.60
  • Adicionar compasso após tipo: [classic verse 7/8 intensity=0.2-0.7] para grooves compasso ímpar
  • Linhas instrumento: Uma linha por instrumento. Formato: INSTRUMENTO PASSO PASSO PASSO | PASSO PASSO PASSO
  • K = bumbo, S = caixa, RS = ride curto, SS = splash, H = hi-hat, HO = hi-hat aberto, HP = pedal hi-hat, R = tom rack, RB = tom grave, C = crash, C2 = segundo crash, CH = china, SP = splash, T1 = tom 1, T2 = tom 2, T3 = tom 3, T4 = tom 4
  • Caracteres passo: . = pausa (sem golpe), x = golpe, X = golpe acentuado, o = nota suave, g = ghost note
  • Espaços dentro compasso ignorados (só melhoram legibilidade)
  • Compassos separados por |. Motor usa contagem compassos linha mais longa; linhas mais curtas repetem seus compassos.
  • Exemplo (de rock.tab):
[rock verse intensity=0.20-0.60]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.

7. Sistema Fills (ComposerV2.pas)

Fills carregados de config/fills/.tab. Cada bloco define nome/banda energia. Motor escolhe fill cuja energia corresponde intensidade compasso nos limites seção.

Formato bloco fill:

[bonham_fill_short energy=0.3]
S ... ... ... xxx
  • Header: [name energy=0.3]
  • name — ex. bonham_fill_short, peart_fill_odd_7_8
  • energy=0.3 — intensidade compasso (0–1) que fill encaixa melhor
  • Mesmo formato instrumento/passo que grooves: Mesmos caracteres passo (., x, X, o, g), mesmas regras separador compasso/compassos.

8. Humanização (AdvancedHumanization.pas)

Jitter timing e velocity aplicados por nota, escalados por configuração humanização. Ghost notes e accents preservados.

  • Jitter timing: Cada nota deslocada alguns ms para frente/trás. Pequeno o suficiente para sentir natural, grande o suficiente para evitar efeito "metralhadora".
  • Variação velocity: Alguns golpes ligeiramente mais fortes/suaves que esperado.
  • Swing: Sensação onde colcheias retas tocadas com leve proporção 2:1 ou 3:1, como groove rock/funk clássico. Controlado por flag interface de linha de comando --swing ou controle interface gráfica (0 = reto, 0.67 = clássico 2:1, 1 = 3:1).

Controla tudo com controle Humanização interface gráfica (0–1). Em 0, perfeito na grade. Em 1, feeling máximo.

9. Restrições Físicas (PhysicalConstraints.pas / PatternFixer.pas)

Corretor pattern remove golpes impossíveis:

  • Máx 3 golpes num passo: Baterista não pode tocar bumbo, caixa, e dois toms de vez em um movimento.
  • Padrões coordenação membros:
    • Mão direita: tipicamente toca crash ou ride
    • Mão esquerda: hi-hat ou ride
    • Pé direito: pedal bumbo
    • Pé esquerdo: pedal hi-hat
  • Impede motor gerar patterns que baterista real não poderia tocar fisicamente.

10. Arquitetura Plugins (PluginRegistry.pas, DrumGenerator.pas)

Plugins gênero e baterista compilados no executável. Cada baterista aplica 2–4 modificações:

  • BehindBeat: Baterista toca ligeiramente atrás do tempo para feeling relaxado.
  • GhostNotes: Adiciona rim-shots sutis e notas silenciosas.
  • LinearCoordination: Padrões membros típicos este baterista (ex. patterns característicos bumbo-caixa Bonham).
  • ShuffleFeel: Feeling swing específico este estilo.
  • FillPatterns: Vocabulário fill típico este baterista.

Modificações componíveis e aplicadas em ordem. Plugins gênero (Metal, Rock, Jazz, Funk, Electronic) definem bandas intensidade típicas, quais grooves fazem sentido para estilo, e estrutura música padrão.

11. Sistema Keymap (Kit.pas)

Notas MIDI resolvidas via arquivos JSON keymap em mappings/. Nenhuma nota hardcodada existe no código Pascal.

  • Arquivos keymap mapeiam nomes notas (kick, snare, hi-hat, tom1, crash, etc.) para notas MIDI.
  • Mesmo motor geração pode usar qualquer keymap — GM, AD2, EZDrummer 3, Yamaha XG, ou usuário.
  • Pode editar arquivos JSON keymap personalizar qual nota dispara qual tambor.

    • Por isso sistema funciona com tantas libs bateria diferentes e interface gráfica não hardcodeia nomes tambores.

12. Exportação MIDI (MidiIO.pas, MidiParser.pas)

Escritor SMF Formato 0 bruto com codificação VLQ, eventos meta tempo/compasso, compatível todas DAWs e VSTs bateria.

  • Tracks: Uma pista MIDI contendo todas notas bateria.
  • Eventos tempo: Mudanças BPM enquanto música progride.
  • Eventos compasso: Mudanças assinatura tempo.
  • Dados nota: Altura (qual tambor), velocity, tempo início, duração.

Este arquivo MIDI funciona com qualquer DAW (Reaper, Ardour, Ableton, Logic, etc.) e qualquer plugin VST bateria (EZDrummer, Superior Drummer, Addictive Drums, etc.).

O Programa de Interface Gráfica

A interface gráfica (chameleondrummer_gui.exe) liga motor diretamente — produz exatamente o que ferramenta linha comando produz, sem invocá-la.

  1. Inicie chameleondrummer_gui.exe.
  2. Escolha gênero, estilo, baterista, keymap, tempo, complexidade, humanização da interface.
  3. Clique Gerar — arquivo MIDI escrito.
  4. Opcionalmente exporte projeto REAPER (.rpp) ou sessão Ardour (.ardour) ao lado.
  5. Dark mode disponível via Ver > Sistema/Claro/Escuro e persiste em gui.ini.

Interface gráfica fornece acesso interativo a todas opções geração interface de linha de comando mais feedback visual:

  • Pré-visualização tempo real combinações gênero/estilo/baterista selecionadas
  • Controles seção dinâmicos adicionados runtime baseados em padrões gênero
  • Suporte Dark mode (compilado só Windows)
  • Persistência configuração via gui.ini

Veja gui/README.md para detalhes layout formulário Lazarus, configuração componentes, implementação dark mode.

Interface gráfica também inclui botão Step Editor abrindo aplicação standalone step editor (tools/step_editor/step_editor.exe). Step editor permite editar visualmente patterns bateria em grade passos, converter arquivos MIDI formato tab, salvar patterns como grooves ou fills. Veja Step Editor para detalhes.

Integração REAPER

ChameleonDrummer integra com REAPER via painel Lua (reaper_chameleon/chameleon_panel.lua) que impulsiona interface de linha de comando para geração bateria e importa resultados diretamente no projeto REAPER.

Instalação

  1. Copie diretório reaper_chameleon/ para pasta scripts REAPER.
  2. Abra REAPER e carregue chameleon_panel.lua via Actions > Show action list > New > ReaScript.
  3. Painel aparece como janela ancorável com quatro abas.

Abas

Song Sections

  • Selecione gênero, estilo, baterista, mapping, tempo, número compassos
  • Gere MIDI via interface de linha de comando e importe no projeto REAPER atual
  • Exporte projeto REAPER (.rpp) junto ao MIDI

Additive Rhythm

  • Insira notação agrupamento aditivo (ex. 3-3-3-3-2-2)
  • Defina resolução grid (4, 8, 16, 32), tempo, baterista, intensidade
  • Gere patterns ritmo aditivo com assinaturas tempo por compasso
  • Exportação opcional timeline JSON para marcadores tempo REAPER

Step Editor

  • Carregue item MIDI do projeto atual
  • Edite em grid com aplicação baterista (variância timing/velocity)
  • Aplique estilo baterista a patterns existentes

Settings

  • Configure caminho executável interface de linha de comando
  • Defina gênero/estilo/baterista/mapping padrão
  • Atualize opções de comandos interface de linha de comando list

Log

  • Saída log tempo real comandos interface de linha de comando
  • Mensagens status durante geração

O Programa de Interface de Linha de Comando

Referência Comandos

Usage: chameleondrummer  [options]

Commands:
  generate         Generate a complete song (multi-bar pattern)
  pattern          Generate a single 1-4 bar pattern
  list             List available genres, styles, drummers, or mappings
  info             Show system information
  reaper           Create a REAPER project (sub-command: export)
  ardour           Create an Ardour session (sub-command: export)
  additive-rhythm  Generate additive rhythm patterns

Options:
  --genre               Genre (metal, rock, jazz, funk, electronic)
  --style               Style within genre (heavy, classic, swing, ...)
  --tempo                Tempo in BPM (default: genre/style value)
  --complexity <0-1>          Pattern complexity (default: 0.5)
  --humanization <0-1>        Humanization intensity (default: 0.3)
  --swing <0-1>               Swing feel: 0 = straight (default), 0.67 = classic 2:1, 1 = 3:1
  --time-sig             Meter of the song, e.g. 3/4, 5/4, 7/8, 9/8, 11/8, 13/8 (default 4/4)
  --strict-meter              Only use patterns matching --time-sig
  --segment   A section with its own tempo and meter, e.g. bridge:4:96:7/8
                              (bpm - keeps the song tempo); mix freely with --section
  --section     Song structure; repeat once per section, in order
                              e.g. --section intro:4 --section verse:8 --section chorus:8@140
                              (without --section the genre default structure is used)
  --drummer             Drummer style (e.g., bonham, peart, carey)
  --output              Output MIDI file path
  --reaper, --ardour          With generate: also write .rpp / the .ardour session
  --mapping             Keymap to use: gm (default), ad2, ezd3, xg
  --structure           Song structure from a JSON file (sections with bars, tempo,
                              complexity; optional genre, style, tempo). Command-line
                              genre/style/tempo win over the file. Not with --section.
  --sidecar             Same as --structure (the REAPER sidecar format works)
  --song-map            Read song map JSON for per-bar tempo/meter
  --write-timeline            Write timeline JSON after generation
  --list                List: genres, styles, drummers, mappings
  --json                      Output JSON for list commands
  --grouping             Additive grouping notation (e.g., 3-3-3-3-2-2)
  --grid                   Grid resolution for additive-rhythm (4, 8, 16, 32)
  --drummer-intensity <0-1>   Drummer intensity for additive-rhythm
  --help, -h                  Show this help

Exemplos

Gerar música completa:

ChameleonDrummer.exe generate --genre metal --style death --tempo 195 --drummer hoglan --mapping ad2 --output death_metal.mid

Gerar padrão único:

ChameleonDrummer.exe pattern --genre jazz --style swing --output swing_verse.mid

Criar projeto REAPER:

ChameleonDrummer.exe reaper export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.rpp

Criar sessão Ardour:

ChameleonDrummer.exe ardour export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.ardour

Padrão ritmo aditivo:

ChameleonDrummer.exe additive-rhythm --grouping "3-3-3-3-2-2" --grid 16 --tempo 120 --mapping gm --drummer bonham --drummer-intensity 0.8 --output additive.mid

Recursos Avançados

Song Maps e Sidecars

Sections (--section): Descreve estrutura música diretamente na linha comando, um --section por seção, ordem reprodução:

ChameleonDrummer.exe generate --genre metal --style death --section intro:4 --section verse:8 --section chorus:8 --section bridge:4 --output song.mid

Sidecar (--sidecar): Arquivo JSON descrevendo seções com compassos, tempo, complexidade, overrides opcionais gênero/estilo/tempo. Gênero/estilo/tempo linha comando ganham sobre arquivo.

Song Map (--song-map): Arquivo JSON descrevendo mudanças tempo/compasso por compasso para músicas progressivas complexas.

Compassos Ímpares

Motor suporta compassos 2/4 a 32/16. Use --time-sig n/d ou --segment para especificar. Grooves e fills carregados de arquivos .tab declarando seu compasso no header bloco (ex. [metal verse 7/8 intensity=0.40-0.90]).

Seus Próprios Grooves, Fills e Defaults

Edite arquivos em config/:

  • config/grooves/.tab — adicionar novos grooves, mudar bandas intensidade
  • config/fills/.tab — adicionar novos fills, mudar níveis energia
  • config/defaults/.ini — mudar tempo/estilo/baterista padrão
  • config/sections/.json — mudar estrutura música padrão

Sem recompilação necessária — motor lê estes em runtime.

Ordem Busca

  1. Pasta na variável ambiente CHAMELEON_CONFIG, se definida
  2. %APPDATA%\ChameleonDrummer\config (Linux: ~/.config/ChameleonDrummer/config)
  3. config ao lado do programa
  4. ..\config (builds desenvolvimento)

Conversão MIDI → Tab

tools/midi_to_tab.exe converte arquivo MIDI para formato groove/fill .tab. Compilado de Pascal, sem dependências externas.

midi_to_tab.exe input.mid [output.tab]
midi_to_tab.exe input.mid --fill --name bonham_fill --energy 0.6
midi_to_tab.exe input.mid --meter 7/8 --resolution 16
midi_to_tab.exe input.mid --mapping mappings/gm.json --style rock --kind verse

Step Editor

O Step Editor (tools/step_editor/step_editor.exe) é aplicação gráfica standalone para editar visualmente patterns bateria em grade passos, converter arquivos MIDI para formato .tab groove/fill, e gerenciar blocos patterns em arquivos config. Lançável desde interfaz gráfica principal via botão Step Editor, ou executável diretamente.

Lançamento Step Editor

  • Desde interface gráfica: Clique botão Step Editor na barra ferramentas janela principal.
  • Diretamente: Execute tools/step_editor/step_editor.exe da raiz projeto ou diretório instalação.
  • Desde painéis REAPER/Ardour: Aba Step Editor em painéis integração DAW lança editor com item MIDI atual carregado.

Recursos Principais

  • Edição Grade Passos: Grade visual 17 instrumentos bateria (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4) e passos configuráveis por compasso (4, 8, 16, 32, 64).
  • Caracteres Velocity/Articulação: Cada passo usa caractere: . (pausa), x (normal), X (acento), o (suave/ghost), g (ghost). Clique células para ciclar estados.
  • Conversão MIDI → Tab: Carregue arquivo MIDI (.mid, .midi) e converta formato tab via midi_to_tab.exe integrado com mapping, estilo, tipo, intensidade, energia, resolução, compasso configuráveis.
  • Carregamento Arquivos Tab: Carregue arquivos .tab existentes (formato config ChameleonDrummer e formatos tab estrangeiros) para edição.
  • Navegação Blocos (Arquivos Config): Carregando arquivo config de config/grooves/ ou config/fills/, editor parseia todos blocos pattern e fornece seletor dropdown com botões Prev/Next navegação entre blocos.
  • Edição Blocos: Edite campos header bloco (Estilo, Tipo, Intensidade Low/High) diretamente na UI. Mudanças marcadas com indicador *.
  • Salvamento Cirúrgico: Salve blocos individuais de volta ao arquivo fonte sem afetar outros blocos mesmo arquivo.
  • Novos/Excluir Blocos: Adicione novos blocos pattern vazios ou exclua existentes (com confirmação).
  • Zoom/Resolução: Mude resolução grade (8, 16, 32, 64 passos por compasso) e tamanho página.
  • Dark Mode: Detecção automática tema sistema (Windows) com override manual. Todos controles incluindo grade, combo boxes, barra status são themed.
  • Auto-Scaling: Escalonamento vetorial proporcional todos elementos UI para displays high-DPI.
  • Exportar: Salve patterns editados como novos arquivos groove/fill .tab nos diretórios config.

Conversão MIDI → Tab

Ao selecionar arquivo MIDI (.mid, .midi), editor executa auto midi_to_tab.exe com configurações UI atuais e mostra resultado na grade.

Parâmetros Conversão (da UI):

  • Mapping: Arquivo JSON keymap (padrão: GM integrado).
  • Style: Nome estilo groove (ex. metal, rock, jazz).
  • Kind: Tipo groove (verse, chorus, bridge, intro, outro, fill).
  • Intensity: Banda grooves (ex. 0.2-0.6).
  • Energy: Nível fills (0.1–1.0).
  • Resolution: Passos por semicolcheia (4, 8, 16, 32).
  • Meter: Assinatura tempo (ex. 4/4, 7/8, 4/4T feel tríades).
  • Fill Mode: Ativado = sai bloco fill em vez groove.

Saída bruta conversão mostrada log status para debug.

Formatos Arquivo Tab

Editor lida com dois formatos tab:

1. Formato Config ChameleonDrummer (config/grooves/*.tab, config/fills/*.tab)

Múltiplos blocos pattern um arquivo, cada com header:

[metal verse intensity=0.20-0.60]
K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...
|
K   x.x.x.x.x.x.x.x
...

[metal chorus intensity=0.40-0.80]
K   x.x.x.x.x.x.x.x
...

Carregando arquivo config, editor:

  • Parseia todos blocos e preenche seletor dropdown blocos.
  • Mostra UI navegação blocos (seletor, Prev/Next, campos header editáveis).
  • Permite salvamento cirúrgico blocos individuais sem reescrever todo arquivo.

2. Formato Tab Estrangeiro (pattern único, sem headers bloco)

Formato simples só linhas instrumento:

K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...

Carregados como pattern único editável sem navegação blocos.

Edição Grade Passos

  • Clique célula para ciclar: . → x → X → o → g → .
  • Seleção intervalo: Arraste selecionar múltiplas células. Use Save Pattern As exportar só região selecionada.
  • Abreviações instrumento: Coluna esq fixa (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4).
  • Números passo: Linha topo mostra índice passo dentro cada compasso.
  • Delimitadores compasso: Linhas verticais mais grossas marcam limites compasso.
  • Páginas: Botões Prev/Next Page ou dropdown Zoom navegar patterns grandes.

Gestão Blocos (Só Arquivos Config)

Arquivo config carregado:

  • Seletor Bloco: Dropdown todos blocos formato Style Kind (IntensityLow-IntensityHigh). Blocos modificados sufixo *.
  • Prev/Next: Navegue entre blocos.
  • Campos Header: Edite Style, Kind, Intensity Low, Intensity High direto. Mudanças marcam bloco modificado.
  • Save Block: Escreve só bloco atual de volta ao arquivo fonte (salvamento cirúrgico).
  • New Block: Anexa novo bloco vazio (meter/resolução atual) ao arquivo.
  • Delete Block: Remove bloco atual do arquivo (confirmação requerida, mantém pelo menos um bloco).
