Introducción

ChameleonDrummer es un sistema de generación dinámica de MIDI para batería, construido en Free Pascal (FPC) con la Lazarus Component Library (LCL). Genera patrones de batería realistas para 5 géneros (Metal, Rock, Jazz, Funk, Electronic) con 32 estilos totales, y 17 personalidades de bateristas. Soporta múltiples keymaps MIDI (GM, AD2, EZD3, XG), compases desde 2/4 hasta 32/16 (incluyendo compases impares como 3/4, 5/4, 7/8, 9/8, 11/8, 13/8...), archivos externos de grooves/fills/defaults, exportación de sesiones REAPER .rpp y Ardour .ardour, y humanización avanzada, curvas de intensidad, y restricciones de jugabilidad física.

Se producen dos ejecutables:

  • ChameleonDrummer.exe — interfaz de línea de comandos
  • chameleondrummer_gui.exe — interfaz gráfica (Lazarus/LCL)

Instalación

Requisitos

  • Windows (objetivo principal; Linux/macOS posible con FPC/LCL)
  • Free Pascal Compiler (FPC) 3.2.2+
  • Lazarus IDE (opcional, para desarrollo de interfaz gráfica)
  • Free Pascal Compiler (FPC) 3.2.2+ (para el conversor tools/midi_to_tab.exe)

Compilación desde Fuente

# Ejecutable de interfaz de línea de comandos
cd B:\dev\github\ChameleonDrummer
"%SystemDrive%\lazarus\fpc\3.2.2\bin\x86_64-win64\fpc.exe" -O2 -Fusrc -Sg -Sc ChameleonDrummer.lpr

# Ejecutable de interfaz gráfica
cd gui
cmd /c "build_gui.bat < NUL"

Ejecución del Ejecutable

Ambos ejecutables son autónomos. Coloca ChameleonDrummer.exe y chameleondrummer_gui.exe en el mismo directorio, o referencia la interfaz de línea de comandos desde el directorio de trabajo de la interfaz gráfica.

Inicio Rápido

Interfaz de Línea de Comandos — Generar una Canción Metal

ChameleonDrummer.exe generate --genre metal --style death --tempo 195 --drummer hoglan --mapping ad2 --output death_metal.mid

Interfaz de Línea de Comandos — Generar un Patrón Rock con Estilo Bonham

ChameleonDrummer.exe pattern --genre rock --style classic --drummer bonham --output bonham_verse.mid

Interfaz de Línea de Comandos — Generar en un Compás Impar

ChameleonDrummer.exe generate --genre rock --style classic --time-sig 7/8 --output rock_7_8.mid

ChameleonDrummer.exe list genres
ChameleonDrummer.exe list styles --genre jazz
ChameleonDrummer.exe list drummers
ChameleonDrummer.exe list mappings

Interfaz Gráfica — Generación Interactiva

  1. Lanza chameleondrummer_gui.exe.
  2. Selecciona Género: metal.
  3. Selecciona Estilo: death.
  4. Selecciona Baterista: hoglan.
  5. Selecciona Mapping: ad2.
  6. Establece Tempo: 195.
  7. Ajusta los controles deslizantes de Complejidad y Humanización.
  8. Haz clic en Generar.
  9. Mira la salida en el panel de log.

Conceptos de Generación MIDI de Batería

Esta sección explica los principios subyacentes derivados del código fuente (ComposerV2.pas, DrumGenerator.pas, Pattern.pas, Song.pas, MidiIO.pas).

1. Modelo de Patrón y Pulso (Pattern.pas)

Un TPattern es un contenedor de objetos TBeat. Cada pulso tiene:

  • Posición (Double): Tiempo en pulsos (ej. 0.0, 0.5, 1.0). Posición 1.0 = el segundo pulso, posición 2.0 = el tercer pulso, etc.
  • Instrumento (TDrumInstrument): El instrumento de batería (bombo, caja, hi-hat, etc.). La identidad del instrumento viene de un archivo JSON keymap — ninguna nota está hardcodeada en el código Pascal.
  • Velocity (Integer): Velocity MIDI de 0 (silencio) a 127 (máximo). Esto es lo que hace que algunos golpes suenen más fuertes o suaves.
  • Duración (Double): Longitud de la nota en pulsos. La mayoría de golpes de batería son muy cortos (~0.1 pulsos), pero algunos pueden ser más largos para efecto.
  • GhostNote (Boolean): Nota sutil, de baja velocity para sensación de groove. Piensa en esto como el baterista tocando ligeramente el aro de un tambor entre los golpes principales.
  • Accent (Boolean): Golpe enfatizado. Así es como el baterista pone énfasis en ciertos pulsos (como la caja en los pulsos 2 y 4 en rock).
  • InstrumentPromoted (Boolean): Bandera de procedencia. True solo cuando el instrumento de este pulso fue cambiado in situ por un plugin de género promoviendo un golpe de hi-hat existente a un platillo de mayor energía para una sección de alta energía.

2. Modelo de Canción y Sección (Song.pas)

Un TSong contiene secciones (TSection), cada una con sus propios patrones, fills, tempo y compás. Las secciones se organizan en un orden estándar de canción: intro, verse, pre_chorus, chorus, bridge, breakdown, solo, outro.

Cada sección tiene sus propios:

  • Tempo — velocidad en pulsos por minuto (BPM). 0 significa heredar el tempo de la canción.
  • Compás — la firma de tiempo (4/4, 7/8, 5/4, etc.). El primer número es cuántos pulsos por compás, el segundo valor de nota recibe un pulso.
  • Complejidad — qué tan variados son los patrones. Solo usado cuando HasComplexity está establecido; registros con ceros heredan la complejidad de la canción.
  • Patrones por defecto — qué grooves/fills debe elegir el motor para esta sección.

Las secciones se almacenan en archivos JSON simples. Puedes agregar tus propias secciones, cambiar el orden, o dar a cada sección su propio tempo y compás.

3. Evolución de Patrón Compás por Compás (ComposerV2.pas)

TBarSelector.SelectPatternForPhrase elige un groove para cada compás usando un sorteo aleatorio ponderado:

  • Coincidencia de intensidad: El peso de cada groove se basa en qué tan bien su banda de intensidad encaja con la intensidad del compás. Grooves cuya banda contiene la intensidad del compás obtienen un bono.
  • Ponderación de recencia: El peso del patrón previo se reduce a 0.25× para que pueda volver pero rara vez se repita consecutivamente. Esto evita que el mismo patrón toque compás tras compás.
  • Fases macro: La canción evoluciona en cuatro fases:
    • mpEstablish (compases iniciales): prueba grooves más ligeros para establecer la sensación
    • mpMaintain (compases medios): mantiene lo que funciona
    • mpBuild (hacia el clímax): favorece grooves más pesados, más intensos
    • mpTurnaround (final): lleva de vuelta al inicio o chorus
  • Aleatoriedad thread-safe: La selección usa TThreadedRandom para resultados consistentes entre hilos.

4. Curvas de Intensidad (ComposerV2.pas)

La intensidad varía a lo largo de la canción: intro/verse son más ligeros, chorus es más pesado, bridge/breakdown varían. La curva de intensidad impulsa tanto la selección de patrones como la colocación de fills. Curvas típicas:

  • icAscending — volviéndose más fuerte hacia el clímax
  • icDescending — comenzando fuerte, desvaneciéndose
  • icPlateau — intensidad aproximadamente constante
  • icDipRise — cae luego sube (común para verse-chorus-verse)
  • icSteps — cambios de intensidad distintos en límites de sección

5. Macro Compositor (ComposerV2.pas)

La fase macro sesga la selección de patrón por sección. Las cuatro fases (mpEstablish, mpMaintain, mpBuild, mpTurnaround) controlan cómo evoluciona el groove a lo largo de la canción, como un director musical diciendo "empieza simple, construye energía, luego llévalo a casa."

6. Motor de Groove (ComposerV2.pas)

Los grooves se cargan desde archivos config/grooves/.tab. Cada bloque define un estilo/tipo/banda de intensidad. El motor elige el groove que mejor encaja por compás.

Formato de bloque de groove:

[style kind intensity=low-high]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.
  • Header: [style kind intensity=low-high]
  • style — ej. metal, rock, jazz, funk, electronic
  • kind — verse, chorus o bridge
  • intensity=low-high — las intensidades de compás (0–1) que este groove encaja, ej. intensity=0.20-0.60
  • Añadir compás después del tipo: [classic verse 7/8 intensity=0.2-0.7] para grooves de compás impar
  • Líneas de instrumento: Una línea por instrumento. Formato: INSTRUMENTO PASO PASO PASO | PASO PASO PASO
  • K = bombo, S = caja, RS = ride corto, SS = splash, H = hi-hat, HO = hi-hat abierto, HP = pedal hi-hat, R = tom rack, RB = tom bajo, C = crash, C2 = segundo crash, CH = china, SP = splash, T1 = tom 1, T2 = tom 2, T3 = tom 3, T4 = tom 4
  • Caracteres de paso: . = silencio (sin golpe), x = golpe, X = golpe acentuado, o = nota suave, g = ghost note
  • Espacios dentro de un compás se ignoran (solo mejoran legibilidad)
  • Compases separados por |. El motor usa la cuenta de compases de la línea más larga; líneas más cortas repiten sus compases.
  • Ejemplo (de rock.tab):
[rock verse intensity=0.20-0.60]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.

7. Sistema de Fills (ComposerV2.pas)

Los fills se cargan desde config/fills/.tab. Cada bloque define un nombre/banda de energía. El motor elige un fill cuya energía coincide con la intensidad del compás en límites de sección.

Formato de bloque de fill:

[bonham_fill_short energy=0.3]
S ... ... ... xxx
  • Header: [name energy=0.3]
  • name — ej. bonham_fill_short, peart_fill_odd_7_8
  • energy=0.3 — la intensidad del compás (0–1) que el fill encaja mejor
  • Mismo formato de instrumento/paso que grooves: Mismos caracteres de paso (., x, X, o, g), mismas reglas de separador de compás/compases.

8. Humanización (AdvancedHumanization.pas)

Jitter de timing y velocity se aplican por nota, escalados por la configuración de humanización. Ghost notes y accents se preservan.

  • Jitter de timing: Cada nota se desplaza adelante o atrás por pocos milisegundos. Lo suficientemente pequeño para sentirse natural, lo suficientemente grande para evitar el efecto "ametralladora".
  • Variación de velocity: Algunos golpes son ligeramente más fuertes o suaves de lo esperado.
  • Swing: Una sensación donde las corcheas rectas se tocan con una ligera proporción 2:1 o 3:1, como un groove clásico de rock o funk. Controlado por la flag interfaz de línea de comandos --swing o control deslizante interfaz gráfica (0 = recto, 0.67 = clásico 2:1, 1 = 3:1).

Controlas todo esto con el control deslizante Humanización en la interfaz gráfica (0–1). En 0, está perfectamente en la cuadrícula. En 1, tiene máxima sensación.

9. Restricciones Físicas (PhysicalConstraints.pas / PatternFixer.pas)

El fijador de patrones elimina golpes imposibles:

  • Máximo 3 golpes en un paso: Un baterista no puede golpear bombo, caja, y dos toms a la vez en un movimiento.
  • Patrones de coordinación de miembros:
    • Mano derecha: típicamente toca crash o ride
    • Mano izquierda: hi-hat o ride
    • Pie derecho: pedal de bombo
    • Pie izquierdo: pedal de hi-hat
  • Esto evita que el motor genere patrones que un baterista real no podría tocar físicamente.

10. Arquitectura de Plugins (PluginRegistry.pas, DrumGenerator.pas)

Plugins de género y baterista compilados en el ejecutable. Cada baterista aplica 2–4 modificaciones:

  • BehindBeat: El baterista toca ligeramente detrás del pulso para una sensación relajada.
  • GhostNotes: Añade rim-shots sutiles y notas silenciosas.
  • LinearCoordination: Patrones típicos de miembros para ese baterista (ej. patrones característicos de bombo-caja de Bonham).
  • ShuffleFeel: Sensación de swing específica para ese estilo.
  • FillPatterns: Vocabulario típico de fills para ese baterista.

Las modificaciones son componibles y se aplican en orden. Plugins de género (Metal, Rock, Jazz, Funk, Electronic) definen las bandas de intensidad típicas, qué grooves tienen sentido para ese estilo, y la estructura de canción por defecto.

11. Sistema de Keymap (Kit.pas)

Las notas MIDI se resuelven a través de archivos JSON keymap en mappings/. No existen notas hardcodeadas en el código Pascal.

  • Los archivos keymap mapean nombres de notas (kick, snare, hi-hat, tom1, crash, etc.) a notas MIDI.
  • El mismo motor de generación puede usar cualquier keymap — GM, AD2, EZDrummer 3, Yamaha XG, o creado por el usuario.
  • Puedes editar archivos JSON keymap para personalizar qué nota dispara qué tambor.

    • Por eso el sistema funciona con tantas librerías de batería diferentes y por qué la interfaz gráfica no hardcodea nombres de tambores.

12. Exportación MIDI (MidiIO.pas, MidiParser.pas)

Escritor SMF Formato 0 crudo con codificación VLQ, eventos meta de tempo/compás, compatible con todas las DAWs y VSTs de batería.

  • Tracks: Una pista MIDI conteniendo todas las notas de batería.
  • Eventos de tempo: Cambios de BPM mientras la canción avanza.
  • Eventos de compás: Cambios de firma de tiempo.
  • Datos de nota: Tonaltidad (qué tambor), velocity, tiempo de inicio, duración.

Este archivo MIDI funciona con cualquier DAW (Reaper, Ardour, Ableton, Logic, etc.) y cualquier plugin VST de batería (EZDrummer, Superior Drummer, Addictive Drums, etc.).

El Programa de Interfaz Gráfica

La interfaz gráfica (chameleondrummer_gui.exe) enlaza el motor directamente — produce exactamente lo que la herramienta de línea de comandos produce, sin invocarla.

  1. Lanza chameleondrummer_gui.exe.
  2. Elige género, estilo, baterista, keymap, tempo, complejidad y humanización desde la interfaz.
  3. Haz clic en Generar — se escribe un archivo MIDI.
  4. Opcionalmente exporta un proyecto REAPER (.rpp) o sesión Ardour (.ardour) junto a él.
  5. Dark mode disponible vía Ver > Sistema/Claro/Oscuro y persiste en gui.ini.

La interfaz gráfica proporciona acceso interactivo a todas las opciones de generación de interfaz de línea de comandos más retroalimentación visual:

  • Vista previa en tiempo real de combinaciones género/estilo/baterista seleccionadas
  • Controles de sección dinámicos añadidos en tiempo de ejecución basados en defaults de género
  • Soporte Dark mode (compilado solo para Windows)
  • Persistencia de configuración vía gui.ini

Ver gui/README.md para detalles del layout del formulario Lazarus, configuración de componentes, e implementación de dark mode.

La interfaz gráfica también incluye un botón Step Editor que abre la aplicación standalone del step editor (tools/step_editor/step_editor.exe). El step editor te permite editar visualmente patrones de batería en una cuadrícula de pasos, convertir archivos MIDI a formato tab, y guardar patrones como grooves o fills. Ver Step Editor para detalles.

Integración REAPER

ChameleonDrummer se integra con REAPER vía un panel Lua (reaper_chameleon/chameleon_panel.lua) que impulsa la interfaz de línea de comandos para generación de batería e importa resultados directamente a tu proyecto REAPER.

Instalación

  1. Copia el directorio reaper_chameleon/ a tu carpeta de scripts de REAPER.
  2. Abre REAPER y carga chameleon_panel.lua vía Actions > Show action list > New > ReaScript.
  3. El panel aparece como ventana andockable con cuatro pestañas.

Pestañas

Song Sections

  • Selecciona género, estilo, baterista, mapping, tempo, y número de compases
  • Genera MIDI vía interfaz de línea de comandos e importa al proyecto REAPER actual
  • Exporta proyecto REAPER (.rpp) junto al MIDI

Additive Rhythm

  • Introduce notación de agrupación aditiva (ej. 3-3-3-3-2-2)
  • Establece resolución de grid (4, 8, 16, 32), tempo, baterista, intensidad
  • Genera patrones de ritmo aditivo con firmas de tiempo por compás
  • Exportación opcional de timeline JSON para marcadores de tempo REAPER

Step Editor

  • Carga un item MIDI del proyecto actual
  • Edita en una grid con aplicación de baterista (variación timing/velocity)
  • Aplica estilo de baterista a patrones existentes

Settings

  • Configura ruta del ejecutable interfaz de línea de comandos
  • Establece género/estilo/baterista/mapping por defecto
  • Actualiza opciones desde comandos interfaz de línea de comandos list

Log

  • Salida de log en tiempo real de comandos interfaz de línea de comandos
  • Mensajes de estado durante la generación

El Programa de Interfaz de Línea de Comandos

Referencia de Comandos

Usage: chameleondrummer  [options]

Commands:
  generate         Generate a complete song (multi-bar pattern)
  pattern          Generate a single 1-4 bar pattern
  list             List available genres, styles, drummers, or mappings
  info             Show system information
  reaper           Create a REAPER project (sub-command: export)
  ardour           Create an Ardour session (sub-command: export)
  additive-rhythm  Generate additive rhythm patterns

Options:
  --genre               Genre (metal, rock, jazz, funk, electronic)
  --style               Style within genre (heavy, classic, swing, ...)
  --tempo                Tempo in BPM (default: genre/style value)
  --complexity <0-1>          Pattern complexity (default: 0.5)
  --humanization <0-1>        Humanization intensity (default: 0.3)
  --swing <0-1>               Swing feel: 0 = straight (default), 0.67 = classic 2:1, 1 = 3:1
  --time-sig             Meter of the song, e.g. 3/4, 5/4, 7/8, 9/8, 11/8, 13/8 (default 4/4)
  --strict-meter              Only use patterns matching --time-sig
  --segment   A section with its own tempo and meter, e.g. bridge:4:96:7/8
                              (bpm - keeps the song tempo); mix freely with --section
  --section     Song structure; repeat once per section, in order
                              e.g. --section intro:4 --section verse:8 --section chorus:8@140
                              (without --section the genre default structure is used)
  --drummer             Drummer style (e.g., bonham, peart, carey)
  --output              Output MIDI file path
  --reaper, --ardour          With generate: also write .rpp / the .ardour session
  --mapping             Keymap to use: gm (default), ad2, ezd3, xg
  --structure           Song structure from a JSON file (sections with bars, tempo,
                              complexity; optional genre, style, tempo). Command-line
                              genre/style/tempo win over the file. Not with --section.
  --sidecar             Same as --structure (the REAPER sidecar format works)
  --song-map            Read song map JSON for per-bar tempo/meter
  --write-timeline            Write timeline JSON after generation
  --list                List: genres, styles, drummers, mappings
  --json                      Output JSON for list commands
  --grouping             Additive grouping notation (e.g., 3-3-3-3-2-2)
  --grid                   Grid resolution for additive-rhythm (4, 8, 16, 32)
  --drummer-intensity <0-1>   Drummer intensity for additive-rhythm
  --help, -h                  Show this help

Ejemplos

Generar una canción completa:

ChameleonDrummer.exe generate --genre metal --style death --tempo 195 --drummer hoglan --mapping ad2 --output death_metal.mid

Generar un patrón individual:

ChameleonDrummer.exe pattern --genre jazz --style swing --output swing_verse.mid

Crear proyecto REAPER:

ChameleonDrummer.exe reaper export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.rpp

Crear sesión Ardour:

ChameleonDrummer.exe ardour export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.ardour

Patrón de ritmo aditivo:

ChameleonDrummer.exe additive-rhythm --grouping "3-3-3-3-2-2" --grid 16 --tempo 120 --mapping gm --drummer bonham --drummer-intensity 0.8 --output additive.mid

Características Avanzadas

Song Maps y Sidecars

Sections (--section): Describe la estructura de la canción directamente en la línea de comandos, un --section por sección, en orden de reproducción:

ChameleonDrummer.exe generate --genre metal --style death --section intro:4 --section verse:8 --section chorus:8 --section bridge:4 --output song.mid

Sidecar (--sidecar): Un archivo JSON describiendo secciones con compases, tempo, complejidad, y overrides opcionales de género/estilo/tempo. Los género/estilo/tempo de línea de comandos ganan sobre el archivo.

Song Map (--song-map): Un archivo JSON describiendo cambios de tempo y compás por compás para canciones progresivas complejas.

Compases Impares

El motor soporta compases desde 2/4 hasta 32/16. Usa --time-sig n/d o --segment para especificar. Grooves y fills se cargan desde archivos .tab que declaran su compás en el header del bloque (ej. [metal verse 7/8 intensity=0.40-0.90]).

Tus Propios Grooves, Fills y Defaults

Edita archivos en config/:

  • config/grooves/.tab — agregar nuevos grooves, cambiar bandas de intensidad
  • config/fills/.tab — agregar nuevos fills, cambiar niveles de energía
  • config/defaults/.ini — cambiar tempo/estilo/baterista por defecto
  • config/sections/.json — cambiar estructura de canción por defecto

No se necesita recompilación — el motor lee estos en tiempo de ejecución.

Orden de Búsqueda

  1. La carpeta en la variable de entorno CHAMELEON_CONFIG, si está establecida
  2. %APPDATA%\ChameleonDrummer\config (Linux: ~/.config/ChameleonDrummer/config)
  3. config junto al programa
  4. ..\config (builds de desarrollo)

Conversión MIDI → Tab

tools/midi_to_tab.exe convierte un archivo MIDI al formato groove/fill .tab. Compilado desde Pascal, sin dependencias externas.

midi_to_tab.exe input.mid [output.tab]
midi_to_tab.exe input.mid --fill --name bonham_fill --energy 0.6
midi_to_tab.exe input.mid --meter 7/8 --resolution 16
midi_to_tab.exe input.mid --mapping mappings/gm.json --style rock --kind verse

Opciones

OpciónDescripción
--fillGenerar un bloque fill en lugar de groove
--name Nombre del fill (default: fill)
--energy <0-1>Energía del fill (default: 0.5)
--meter Override de compás (default: de MIDI meta o 4/4)
--resolution Pasos por corchea: 4, 8, 16, 32 (default: 16)
--mapping Archivo JSON keymap (default: GM map integrado)
--style Nombre de estilo groove (default: midi)
--kind Tipo de groove: verse/chorus/bridge (default: verse)
--intensity Banda de intensidad groove (default: 0.2-0.6)

La salida se escribe con finales de línea CRLF, lista para colocar en config/grooves/ o config/fills/.

Step Editor

El Step Editor (tools/step_editor/step_editor.exe) es una aplicación gráfica standalone para editar visualmente patrones de batería en una cuadrícula de pasos, convertir archivos MIDI al formato .tab groove/fill, y gestionar bloques de patrones en los archivos de configuración. Puede lanzarse desde la interfaz gráfica principal vía el botón Step Editor, o ejecutarse directamente.

Lanzamiento del Step Editor

  • Desde la interfaz gráfica: Haz clic en el botón Step Editor en la barra de herramientas de la ventana principal.
  • Directamente: Ejecuta tools/step_editor/step_editor.exe desde la raíz del proyecto o directorio de instalación.
  • Desde paneles REAPER/Ardour: La pestaña Step Editor en los paneles de integración DAW lanza el editor con el item MIDI actual cargado.

Características Principales

  • Edición de Grid de Pasos: Grid visual con 17 instrumentos de batería (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4) y pasos configurables por compás (4, 8, 16, 32, 64).
  • Caracteres de Velocity/Articulación: Cada paso usa un carácter: . (silencio), x (normal), X (acento), o (suave/ghost), g (ghost). Haz clic en celdas para ciclar estados.
  • Conversión MIDI → Tab: Carga un archivo MIDI (.mid, .midi) y conviértelo a formato tab usando el midi_to_tab.exe integrado con mapping, estilo, tipo, intensidad, energía, resolución, y compás configurables.
  • Carga de Archivos Tab: Carga archivos .tab existentes (tanto formato config ChameleonDrummer como formatos tab extranjeros) para edición.
  • Navegación de Bloques (Archivos Config): Al cargar un archivo config de config/grooves/ o config/fills/, el editor parsea todos los bloques de patrón y provee un selector dropdown con botones Prev/Next para navegar entre bloques.
  • Edición de Bloques: Edita campos de header de bloque (Estilo, Tipo, Intensidad Low/High) directamente en la UI. Cambios se marcan con indicador *.
  • Guardado Quirúrgico: Guarda bloques individuales de vuelta a su archivo fuente sin afectar otros bloques en el mismo archivo.
  • Nuevos/Eliminar Bloques: Añade nuevos bloques de patrón vacíos o elimina existentes (con confirmación).
  • Zoom/Resolución: Cambia resolución de grid (8, 16, 32, 64 pasos por compás) y tamaño de página.
  • Dark Mode: Detección automática de tema del sistema (Windows) con override manual. Todos los controles incluyendo grid, combo boxes, y barra de estado son themed.
  • Auto-Scaling: Escalado vectorial proporcional de todos los elementos UI para displays high-DPI.
  • Exportar: Guarda patrones editados como nuevos archivos groove o fill .tab en los directorios config.

Conversión MIDI → Tab

Al seleccionar un archivo MIDI (.mid, .midi), el editor ejecuta automáticamente midi_to_tab.exe con la configuración UI actual y muestra el resultado en la grid.

Parámetros de Conversión (desde UI):

  • Mapping: Archivo JSON keymap (default: GM integrado).
  • Style: Nombre de estilo groove (ej. metal, rock, jazz).
  • Kind: Tipo de groove (verse, chorus, bridge, intro, outro, fill).
  • Intensity: Banda para grooves (ej. 0.2-0.6).
  • Energy: Nivel para fills (0.1–1.0).
  • Resolution: Pasos por corchea (4, 8, 16, 32).
  • Meter: Firma de tiempo (ej. 4/4, 7/8, 4/4T para feel de tríadas).
  • Fill Mode: Cuando activado, genera bloque fill en lugar de groove.

La salida cruda de conversión se muestra en el log de estado para depuración.

Formatos de Archivo Tab

El editor maneja dos formatos de archivo tab:

1. Formato Config ChameleonDrummer (config/grooves/*.tab, config/fills/*.tab)

Múltiples bloques de patrón en un archivo, cada uno con header:

[metal verse intensity=0.20-0.60]
K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...
|
K   x.x.x.x.x.x.x.x
...

[metal chorus intensity=0.40-0.80]
K   x.x.x.x.x.x.x.x
...

Al cargar un archivo config, el editor:

  • Parsea todos los bloques y llena el selector dropdown de bloques.
  • Muestra UI de navegación de bloques (selector, Prev/Next, campos header editables).
  • Permite guardado quirúrgico de bloques individuales sin reescribir todo el archivo.

2. Formato Tab Extranjero (patrón único, sin headers de bloque)

Formato simple con solo líneas de instrumento:

K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...

Estos se cargan como un único patrón editable sin navegación de bloques.

Edición de Grid de Pasos

  • Haz clic en una celda para ciclar: . → x → X → o → g → .
  • Selección de rango: Arrastra para seleccionar múltiples celdas. Usa Save Pattern As para exportar solo la región seleccionada.
  • Abreviaturas de instrumento: Columna izquierda fija (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4).
  • Números de paso: Fila superior muestra índice de paso dentro de cada compás.
  • Delimitadores de compás: Líneas verticales más gruesas marcan límites de compás.
  • Páginas: Usa botones Prev/Next Page o dropdown Zoom para navegar patrones grandes.

Gestión de Bloques (Solo Archivos Config)

Cuando se carga un archivo config:

  • Selector de Bloque: Dropdown mostrando todos los bloques con formato Style Kind (IntensityLow-IntensityHigh). Bloques modificados muestran sufijo *.
  • Prev/Next: Navegar entre bloques.
  • Campos Header: Edita Style, Kind, Intensity Low, Intensity High directamente. Cambios marcan el bloque como modificado.
  • Save Block: Escribe solo el bloque actual de vuelta a su archivo fuente (guardado quirúrgico).
  • New Block: Añade un nuevo bloque vacío (con meter/resolución actual) al archivo.
  • Delete Block: Elimina el bloque actual del archivo (requiere confirmación, mantiene al menos un bloque).
