引导

ChameleonDrummer 是一个动态 MIDI 鼓生成系统，基于 Free Pascal (FPC) 和 Lazarus Component Library (LCL) 构建。它为 5 种风格（Metal、Rock、Jazz、Funk、Electronic）生成逼真的鼓型，共 32 种风格，以及 17 位鼓手个性。支持多种 MIDI keymap (GM, AD2, EZD3, XG)、从 2/4 到 32/16 的拍号（包括 3/4、5/4、7/8、9/8、11/8、13/8... 等奇数拍）、外部 groove/fill/default 文件、REAPER .rpp 和 Ardour .ardour 会话导出，以及高级人性化、强度曲线和物理可演奏性约束。

生成两个可执行文件：

  • ChameleonDrummer.exe — 命令行界面
  • chameleondrummer_gui.exe — 图形界面 (Lazarus/LCL)

安装

要求

  • Windows (主要目标; Linux/macOS 可用 FPC/LCL)
  • Free Pascal Compiler (FPC) 3.2.2+
  • Lazarus IDE (可选, 用于图形用户界面开发)
  • Free Pascal Compiler (FPC) 3.2.2+ (用于 tools/midi_to_tab.exe 转换器)

从源代码构建

# 命令行界面可执行文件
cd B:\dev\github\ChameleonDrummer
"%SystemDrive%\lazarus\fpc\3.2.2\bin\x86_64-win64\fpc.exe" -O2 -Fusrc -Sg -Sc ChameleonDrummer.lpr

# 图形用户界面可执行文件
cd gui
cmd /c "build_gui.bat < NUL"

运行可执行文件

两个可执行文件都是自包含的。将 ChameleonDrummer.exe 和 chameleondrummer_gui.exe 放在同一目录，或从图形用户界面的工作目录引用命令行界面。

快速开始

命令行界面 — 生成 Metal 曲目

ChameleonDrummer.exe generate --genre metal --style death --tempo 195 --drummer hoglan --mapping ad2 --output death_metal.mid

命令行界面 — 生成 Bonham 风格的 Rock 模式

ChameleonDrummer.exe pattern --genre rock --style classic --drummer bonham --output bonham_verse.mid

命令行界面 — 在奇数拍中生成

ChameleonDrummer.exe generate --genre rock --style classic --time-sig 7/8 --output rock_7_8.mid

命令行界面 — 列出可用选项

ChameleonDrummer.exe list genres
ChameleonDrummer.exe list styles --genre jazz
ChameleonDrummer.exe list drummers
ChameleonDrummer.exe list mappings

图形用户界面 — 交互式生成

  1. 启动 chameleondrummer_gui.exe。
  2. 选择 风格: metal。
  3. 选择 风格: death。
  4. 选择 鼓手: hoglan。
  5. 选择 Mapping: ad2。
  6. 设置 速度: 195。
  7. 调整 复杂度 和 人性化 滑块。
  8. 点击 生成。
  9. 在日志面板查看输出。

MIDI 鼓生成概念

本节解释从源代码 (ComposerV2.pas, DrumGenerator.pas, Pattern.pas, Song.pas, MidiIO.pas) 衍生的基本原理。

1. 模式和击打模型 (Pattern.pas)

TPattern 是 TBeat 对象的容器。每个击打有：

  • 位置 (Double): 以拍为单位的时间 (如 0.0, 0.5, 1.0)。位置 1.0 = 第二拍, 位置 2.0 = 第三拍, 等。
  • 乐器 (TDrumInstrument): 鼓乐器 (踩鼓、军鼓、踩镲等)。乐器身份来自 JSON keymap 文件 — Pascal 代码中没有硬编码音符。
  • 力度 (Integer): MIDI 力度从 0 (静音) 到 127 (最大)。这使某些击打听起来更响或更轻。
  • 时长 (Double): 以拍为单位的音符长度。大多数鼓击打很短 (~0.1 拍), 但有些可为效果更长。
  • GhostNote (Boolean): 微妙的低力度音符, 用于 groove 感觉。想象鼓手在主击打之间轻敲鼓边。
  • Accent (Boolean): 重音击打。这是鼓手在特定拍子上加重音的方式 (如摇滚中军鼓在 2 和 4 拍)。
  • InstrumentPromoted (Boolean): 来源标志。仅当该击打的乐器被流派插件就地更改, 将现有踩镲击打提升为高能量镲片用于高能量段落时为 True。

2. 歌曲和段落模型 (Song.pas)

TSong 包含段落 (TSection), 每个有自己的模式、fill、速度和拍号。段落按标准歌曲顺序排列: intro、verse、pre_chorus、chorus、bridge、breakdown、solo、outro。

每个段落有自己的：

  • 速度 — 每分钟拍数 (BPM)。0 表示继承歌曲速度。
  • 拍号 — 时间签名 (4/4, 7/8, 5/4 等)。第一个数字是每小节拍数, 第二个音符值得一拍。
  • 复杂度 — 模式变化程度。仅当 HasComplexity 设置时使用; 零填充记录继承歌曲复杂度。
  • 默认模式 — 引擎应为该段落选择哪些 groove/fill。

段落存储在简单的 JSON 文件中。您可以添加自己的段落、更改顺序, 或给每个段落自己的速度和拍号。

3. 小节逐个模式演变 (ComposerV2.pas)

TBarSelector.SelectPatternForPhrase 使用加权随机抽取为每小节选取 groove：

  • 强度匹配: 每个 groove 的权重基于其强度带与小节强度的契合度。强度带包含小节强度的 groove 获得奖励。
  • 近期加权: 前一个模式的权重降至 0.25×, 使其可返回但极少连续重复。这防止同一模式小节接小节播放。
  • 宏阶段: 歌曲在四个阶段演变:
    • mpEstablish (早期小节): 尝试较轻 groove 确立感觉
    • mpMaintain (中间小节): 保持有效的东西
    • mpBuild (向高潮): 偏好更重、更强烈的 groove
    • mpTurnaround (结尾): 引导回开头或 chorus
  • 线程安全随机性: 选择使用 TThreadedRandom 以跨线程获得一致结果。

4. 强度曲线 (ComposerV2.pas)

强度贯穿歌曲变化: intro/verse 较轻, chorus 较重, bridge/breakdown 变化。强度曲线驱动模式选择和 fill 放置。典型曲线：

  • icAscending — 向高潮变响
  • icDescending — 开始响, 淡出
  • icPlateau — 大致恒定强度
  • icDipRise — 先降后升 (常见 verse-chorus-verse)
  • icSteps — 段落边界处明显的强度变化

5. 宏作曲家 (ComposerV2.pas)

宏阶段对每段落的模式选择施加偏置。四个阶段 (mpEstablish, mpMaintain, mpBuild, mpTurnaround) 控制 groove 如何贯穿歌曲演变, 如音乐总监说 "开始简单, 建立能量, 然后带回家"。

6. Groove 引擎 (ComposerV2.pas)

Groove 从 config/grooves/.tab 文件加载。每个块声明风格/类型/强度带。引擎每小节选取最佳匹配的 groove。

Groove 块格式:

[style kind intensity=low-high]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.
  • Header: [style kind intensity=low-high]
  • style — 如 metal, rock, jazz, funk, electronic
  • kind — verse, chorus 或 bridge
  • intensity=low-high — 此 groove 适合的小节强度 (0–1), 如 intensity=0.20-0.60
  • 类型后添加拍号: [classic verse 7/8 intensity=0.2-0.7] 用于奇数拍 groove
  • 乐器行: 每乐器一行。格式: 乐器 步骤 步骤 步骤 | 步骤 步骤 步骤
  • K = 踩鼓, S = 军鼓, RS = 短镲, SS = 溅镲, H = 踩镲, HO = 开踩镲, HP = 踩镲踏板, R = 架子鼓, RB = 踩鼓, C = 碎镲, C2 = 第二碎镲, CH = 中国镲, SP = 溅镲, T1 = 汤姆 1, T2 = 汤姆 2, T3 = 汤姆 3, T4 = 汤姆 4
  • 步骤字符: . = 休止 (无击打), x = 击打, X = 重音击打, o = 柔和音符, g = ghost note
  • 小节内空格被忽略 (仅提高可读性)
  • 小节用 | 分隔。引擎使用最长行的小节数; 较短行重复其小节。
  • 示例 (来自 rock.tab):
[rock verse intensity=0.20-0.60]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.

7. Fill 系统 (ComposerV2.pas)

Fill 从 config/fills/.tab 加载。每个块声明名称/能量带。引擎在段落边界选取能量匹配小节强度的 fill。

Fill 块格式:

[bonham_fill_short energy=0.3]
S ... ... ... xxx
  • Header: [name energy=0.3]
  • name — 如 bonham_fill_short, peart_fill_odd_7_8
  • energy=0.3 — fill 最适合的小节强度 (0–1)
  • 与 groove 相同的乐器/步骤格式: 相同步骤字符 (., x, X, o, g), 相同小节/分隔规则。

8. 人性化 (AdvancedHumanization.pas)

每音符应用时机和力度抖动, 由人性化设置缩放。Ghost note 和重音保留。

  • 时机抖动: 每个音符前后移动几毫秒。足够小以感觉自然, 足够大以避免 "机枪" 效果。
  • 力度变化: 某些击打比预期稍响或稍轻。
  • Swing: 直八分音符以轻微 2:1 或 3:1 比例演奏的感觉, 如经典摇滚或 funk groove。由 --swing 命令行界面 标志或 图形用户界面 滑块控制 (0 = 直, 0.67 = 经典 2:1, 1 = 3:1)。

您通过图形用户界面中的 人性化 滑块 (0–1) 控制所有这些。0 时完美对齐网格。1 时最大感觉。

9. 物理约束 (PhysicalConstraints.pas / PatternFixer.pas)

模式修复器移除不可能的击打：

  • 单步最多 3 次击打: 鼓手无法在一个动作中同时击打踩鼓、军鼓和两个汤姆鼓。
  • 肢体协调模式:
    • 右手: 通常演奏碎镲或 ride 镲
    • 左手: 踩镲或 ride 镲
    • 右脚: 踩鼓踏板
    • 左脚: 踩镲踏板
  • 这防止引擎生成真实鼓手无法物理演奏的模式。

10. 插件架构 (PluginRegistry.pas, DrumGenerator.pas)

流派插件和鼓手插件编译进可执行文件。每个鼓手应用 2–4 种修改：

  • BehindBeat: 鼓手稍微在拍子后演奏, 营造轻松感觉。
  • GhostNotes: 添加微妙的边缘击打和安静音符。
  • LinearCoordination: 该鼓手典型的肢体模式 (如 Bonham 标志性的踩鼓-军鼓模式)。
  • ShuffleFeel: 特定于该风格的 swing 感觉。
  • FillPatterns: 该鼓手典型的 fill 词汇。

修改可组合且按顺序应用。流派插件 (Metal, Rock, Jazz, Funk, Electronic) 定义典型强度带、哪些 groove 对该风格有意义、以及默认歌曲结构。

11. Keymap 系统 (Kit.pas)

MIDI 音符通过 mappings/ 中的 JSON keymap 文件解析。Pascal 代码中不存在硬编码音符。

  • Keymap 文件将音符名称 (kick, snare, hi-hat, tom1, crash 等) 映射到 MIDI 音符。
  • 相同生成引擎可使用任何 keymap — GM, AD2, EZDrummer 3, Yamaha XG, 或用户创建。
  • 您可编辑 keymap JSON 文件自定义哪个音符触发哪个鼓。

    • 这就是系统能与如此多不同鼓库协作、且图形用户界面不硬编码鼓名称的原因。

12. MIDI 导出 (MidiIO.pas, MidiParser.pas)

原始 SMF 格式 0 写入器, 带 VLQ 编码、速度/拍号元事件, 兼容所有 DAW 和鼓 VST。

  • 轨道: 包含所有鼓音符的单一 MIDI 轨道。
  • 速度事件: 歌曲推进时的 BPM 变化。
  • 拍号事件: 时间签名变化。
  • 音符数据: 音高 (哪个鼓)、力度、开始时间、时长。

此 MIDI 文件适用于任何 DAW (Reaper, Ardour, Ableton, Logic 等) 和任何鼓 VST 插件 (EZDrummer, Superior Drummer, Addictive Drums 等)。

图形用户界面程序

图形用户界面 (chameleondrummer_gui.exe) 直接链接引擎 — 产出与命令行工具完全相同的结果, 无需调用它。

  1. 启动 chameleondrummer_gui.exe。
  2. 从界面选择流派、风格、鼓手、keymap、速度、复杂度和人性化。
  3. 点击 生成 — 写入 MIDI 文件。
  4. 可选导出 REAPER 项目 (.rpp) 或 Ardour 会话 (.ardour)。
  5. Dark mode 可通过 视图 > 系统/浅色/深色 获得, 并持久化在 gui.ini 中。

图形用户界面提供对所有命令行界面生成选项的交互式访问及视觉反馈：

  • 所选流派/风格/鼓手组合的实时预览
  • 基于流派默认值在运行时动态添加的段落控件
  • Dark mode 支持 (仅 Windows 编译)
  • 通过 gui.ini 持久化配置

详见 gui/README.md 了解 Lazarus 表单布局、组件设置和 dark mode 实现。

图形用户界面还包含 Step Editor 按钮, 打开独立的 step editor 应用程序 (tools/step_editor/step_editor.exe)。Step editor 让您在步进网格上可视化编辑鼓模式、将 MIDI 文件转换为 tab 格式、将模式保存为 groove 或 fill。详见 Step Editor。

REAPER 集成

ChameleonDrummer 通过 Lua 面板 (reaper_chameleon/chameleon_panel.lua) 与 REAPER 集成, 该面板驱动命令行界面进行鼓生成并将结果直接导入您的 REAPER 项目。

安装

  1. 将 reaper_chameleon/ 目录复制到 REAPER 脚本文件夹。
  2. 打开 REAPER 并通过 Actions > Show action list > New > ReaScript 加载 chameleon_panel.lua。
  3. 面板作为可停靠窗口出现, 带四个标签页。

标签页

Song Sections

  • 选择流派、风格、鼓手、mapping、速度、小节数
  • 通过命令行界面生成 MIDI 并导入当前 REAPER 项目
  • 导出 REAPER 项目 (.rpp) 与 MIDI 并存

Additive Rhythm

  • 输入加法分组符号 (如 3-3-3-3-2-2)
  • 设置网格分辨率 (4, 8, 16, 32)、速度、鼓手、强度
  • 生成带逐小节拍号的加法节奏模式
  • 可选 timeline JSON 导出用于 REAPER 速度标记

Step Editor

  • 从当前项目加载 MIDI 项
  • 在网格上编辑, 应用鼓手 (时机/力度变化)
  • 将鼓手风格应用于现有模式

Settings

  • 配置 命令行界面 可执行文件路径
  • 设置默认流派/风格/鼓手/mapping
  • 从 命令行界面 list 命令刷新选项

Log

  • 命令行界面 命令的实时日志输出
  • 生成过程中的状态消息

REAPER 面板使用的 命令行界面 命令

ChameleonDrummer list genres --json
ChameleonDrummer list styles --genre metal --json
ChameleonDrummer list drummers --json
ChameleonDrummer list mappings --json
ChameleonDrummer generate --genre X --style Y --mapping Z --tempo N --drummer D --drummer-intensity I --bars B --output file.mid
ChameleonDrummer additive-rhythm --grouping "3-3-3-3-2-2" --grid 16 --tempo 120 --mapping gm --drummer bonham --drummer-intensity 0.8 --output file.mid [--write-timeline timeline.json]

命令行界面程序

命令参考

Usage: chameleondrummer  [options]

Commands:
  generate         Generate a complete song (multi-bar pattern)
  pattern          Generate a single 1-4 bar pattern
  list             List available genres, styles, drummers, or mappings
  info             Show system information
  reaper           Create a REAPER project (sub-command: export)
  ardour           Create an Ardour session (sub-command: export)
  additive-rhythm  Generate additive rhythm patterns

Options:
  --genre               Genre (metal, rock, jazz, funk, electronic)
  --style               Style within genre (heavy, classic, swing, ...)
  --tempo                Tempo in BPM (default: genre/style value)
  --complexity <0-1>          Pattern complexity (default: 0.5)
  --humanization <0-1>        Humanization intensity (default: 0.3)
  --swing <0-1>               Swing feel: 0 = straight (default), 0.67 = classic 2:1, 1 = 3:1
  --time-sig             Meter of the song, e.g. 3/4, 5/4, 7/8, 9/8, 11/8, 13/8 (default 4/4)
  --strict-meter              Only use patterns matching --time-sig
  --segment   A section with its own tempo and meter, e.g. bridge:4:96:7/8
                              (bpm - keeps the song tempo); mix freely with --section
  --section     Song structure; repeat once per section, in order
                              e.g. --section intro:4 --section verse:8 --section chorus:8@140
                              (without --section the genre default structure is used)
  --drummer             Drummer style (e.g., bonham, peart, carey)
  --output              Output MIDI file path
  --reaper, --ardour          With generate: also write .rpp / the .ardour session
  --mapping             Keymap to use: gm (default), ad2, ezd3, xg
  --structure           Song structure from a JSON file (sections with bars, tempo,
                              complexity; optional genre, style, tempo). Command-line
                              genre/style/tempo win over the file. Not with --section.
  --sidecar             Same as --structure (the REAPER sidecar format works)
  --song-map            Read song map JSON for per-bar tempo/meter
  --write-timeline            Write timeline JSON after generation
  --list                List: genres, styles, drummers, mappings
  --json                      Output JSON for list commands
  --grouping             Additive grouping notation (e.g., 3-3-3-3-2-2)
  --grid                   Grid resolution for additive-rhythm (4, 8, 16, 32)
  --drummer-intensity <0-1>   Drummer intensity for additive-rhythm
  --help, -h                  Show this help

示例

生成完整歌曲:

ChameleonDrummer.exe generate --genre metal --style death --tempo 195 --drummer hoglan --mapping ad2 --output death_metal.mid

生成单个模式:

ChameleonDrummer.exe pattern --genre jazz --style swing --output swing_verse.mid

创建 REAPER 项目:

ChameleonDrummer.exe reaper export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.rpp

创建 Ardour 会话:

ChameleonDrummer.exe ardour export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.ardour

加法节奏模式:

ChameleonDrummer.exe additive-rhythm --grouping "3-3-3-3-2-2" --grid 16 --tempo 120 --mapping gm --drummer bonham --drummer-intensity 0.8 --output additive.mid

高级功能

Song Maps 和 Sidecars

Sections (--section): 直接在命令行描述歌曲结构, 每段落一个 --section, 按播放顺序：

ChameleonDrummer.exe generate --genre metal --style death --section intro:4 --section verse:8 --section chorus:8 --section bridge:4 --output song.mid

Sidecar (--sidecar): 描述带小节、速度、复杂度的段落的 JSON 文件, 可选流派/风格/速度覆盖。命令行流派/风格/速度优于文件。

Song Map (--song-map): 描述逐小节速度/拍号变化的 JSON 文件, 用于复杂前卫歌曲。

奇数拍

引擎支持 2/4 到 32/16 的拍号。使用 --time-sig n/d 或 --segment 指定。Groove 和 fill 从在块头声明拍号的 .tab 文件加载 (如 [metal verse 7/8 intensity=0.40-0.90])。

您自己的 Groove、Fill 和默认值

编辑 config/ 中的文件：

  • config/grooves/.tab — 添加新 groove, 更改强度带
  • config/fills/.tab — 添加新 fill, 更改能量级别
  • config/defaults/.ini — 更改默认速度/风格/鼓手
  • config/sections/.json — 更改默认歌曲结构

无需重新编译 — 引擎在运行时读取这些。

查找顺序

  1. 环境变量 CHAMELEON_CONFIG 中的文件夹 (若设置)
  2. %APPDATA%\ChameleonDrummer\config (Linux: ~/.config/ChameleonDrummer/config)
  3. config 程序旁边
  4. ..\config (开发构建)

MIDI → Tab 转换

tools/midi_to_tab.exe 将 MIDI 文件转换为 .tab groove/fill 格式。从 Pascal 编译, 无外部依赖。

midi_to_tab.exe input.mid [output.tab]
midi_to_tab.exe input.mid --fill --name bonham_fill --energy 0.6
midi_to_tab.exe input.mid --meter 7/8 --resolution 16
midi_to_tab.exe input.mid --mapping mappings/gm.json --style rock --kind verse

选项

选项说明
--fill输出 fill 块而非 groove 块
--name Fill 名称 (默认: fill)
--energy <0-1>Fill 能量 (默认: 0.5)
--meter 拍号覆盖 (默认: MIDI 元或 4/4)
--resolution 每四分音符步数: 4, 8, 16, 32 (默认: 16)
--mapping Keymap JSON 文件 (默认: 内置 GM map)
--style Groove 风格名称 (默认: midi)
--kind Groove 类型: verse/chorus/bridge (默认: verse)
--intensity Groove 强度带 (默认: 0.2-0.6)

输出以 CRLF 行尾写入, 可直接放入 config/grooves/ 或 config/fills/。

Step Editor

Step Editor (tools/step_editor/step_editor.exe) 是独立图形应用程序, 用于在步进网格上可视化编辑鼓模式、将 MIDI 文件转换为 .tab groove/fill 格式、管理配置文件中的模式块。可从主 图形用户界面 通过 Step Editor 按钮启动, 或直接运行。

启动 Step Editor

  • 从 图形用户界面: 点击主窗口工具栏的 Step Editor 按钮。
  • 直接: 从项目根目录或安装目录运行 tools/step_editor/step_editor.exe。
  • 从 REAPER/Ardour 面板: DAW 集成面板中的 Step Editor 标签页启动编辑器并加载当前 MIDI 项。

主要功能

  • 步进网格编辑: 17 种鼓乐器 (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4) 的可视化网格, 可配置每小节步数 (4, 8, 16, 32, 64)。
  • 力度/发音字符: 每步使用字符: . (休止), x (正常), X (重音), o (柔和/ghost), g (ghost)。点击单元格循环状态。
  • MIDI → Tab 转换: 加载 MIDI 文件 (.mid, .midi) 并使用内置 midi_to_tab.exe 转换为 tab 格式, 可配置 mapping、风格、类型、强度、能量、分辨率、拍号。
  • Tab 文件加载: 加载现有 .tab 文件 (ChameleonDrummer 配置格式和外部 tab 格式) 进行编辑。
  • 块导航 (配置文件): 从 config/grooves/ 或 config/fills/ 加载配置文件时, 编辑器解析所有模式块, 提供带 Prev/Next 按钮的下拉选择器在块间导航。
  • 块编辑: 直接在 UI 中编辑块头字段 (风格、类型、强度 Low/High)。更改用 * 指示器标记。
  • 手术式保存: 将单个块保存回源文件, 不影响同一文件中的其他块。
  • 新建/删除块: 添加新空模式块或删除现有块 (需确认)。
  • 缩放/分辨率: 更改网格分辨率 (8, 16, 32, 64 步/小节) 和页面大小。
  • Dark Mode: 自动系统主题检测 (Windows) 含手动覆盖。所有控件包括网格、组合框、状态栏均为主题化。
  • Auto-Scaling: 所有 UI 元素的比例矢量缩放, 适配高 DPI 显示器。
  • 导出: 将编辑的模式保存为配置目录中的新 groove 或 fill .tab 文件。

MIDI → Tab 转换

选择 MIDI 文件 (.mid, .midi) 时, 编辑器自动用当前 UI 设置运行 midi_to_tab.exe 并在网格显示结果。

转换参数 (来自 UI):

  • Mapping: Keymap JSON 文件 (默认: 内置 GM)。
  • Style: Groove 风格名称 (如 metal, rock, jazz)。
  • Kind: Groove 类型 (verse, chorus, bridge, intro, outro, fill)。
  • Intensity: Groove 强度带 (如 0.2-0.6)。
  • Energy: Fill 能量级 (0.1–1.0)。
  • Resolution: 每四分音符步数 (4, 8, 16, 32)。
  • Meter: 拍号 (如 4/4, 7/8, 4/4T 三连音 feel)。
  • Fill Mode: 启用时输出 fill 块而非 groove 块。

原始转换输出显示在状态日志中供调试。

Tab 文件格式

编辑器处理两种 tab 文件格式：

1. ChameleonDrummer 配置格式 (config/grooves/*.tab, config/fills/*.tab)

一个文件中多个模式块, 每个带头部：

[metal verse intensity=0.20-0.60]
K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...
|
K   x.x.x.x.x.x.x.x
...

[metal chorus intensity=0.40-0.80]
K   x.x.x.x.x.x.x.x
...

加载配置文件时, 编辑器：

  • 解析所有块并填充块选择器下拉框。
  • 显示块导航 UI (选择器, Prev/Next, 可编辑头字段)。
  • 允许单个块的手术式保存, 无需重写整个文件。

2. 外部 Tab 格式 (单模式, 无块头)

仅含乐器行的简单格式：

K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...

这些作为单个可编辑模式加载, 无块导航。

步进网格编辑

  • 点击单元格 循环: . → x → X → o → g → .
  • 范围选择: 拖拽选择多个单元格。用 Save Pattern As 仅导出选定区域。
  • 乐器缩写: 固定左列 (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4)。
  • 步骤编号: 顶行显示每小节内步骤索引。
  • 小节分隔符: 粗垂直线标记小节边界。
  • 页面: 用 Prev/Next Page 按钮或 Zoom 下拉框导航大模式。

块管理 (仅配置文件)

加载配置文件时：

  • 块选择器: 显示所有块的下拉框, 格式 Style Kind (IntensityLow-IntensityHigh)。修改的块显示 * 后缀。
  • Prev/Next: 块间导航。
  • 头字段: 直接编辑 Style, Kind, Intensity Low, Intensity High。更改标记块为已修改。
  • Save Block: 仅将当前块写回源文件 (手术式保存)。
  • New Block: 向文件追加新空块 (含当前 meter/分辨率)。
  • Delete Block: 从文件移除当前块 (需确认, 保留至少一个块)。
