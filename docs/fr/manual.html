Introduction

ChameleonDrummer est un système de génération dynamique de MIDI pour batterie, construit en Free Pascal (FPC) avec la Lazarus Component Library (LCL). Il génère des motifs de batterie réalistes pour 5 genres (Metal, Rock, Jazz, Funk, Electronic) avec 32 styles au total, et 17 personnalités de batteurs. Il supporte plusieurs keymaps MIDI (GM, AD2, EZD3, XG), mesures de 2/4 à 32/16 (y compris mesures impaires comme 3/4, 5/4, 7/8, 9/8, 11/8, 13/8...), fichiers externes grooves/fills/defaults, export sessions REAPER .rpp et Ardour .ardour, et humanisation avancée, courbes d'intensité, et contraintes de jouabilité physique.

Deux exécutables sont produits :

  • ChameleonDrummer.exe — interface ligne de commande
  • chameleondrummer_gui.exe — interface graphique (Lazarus/LCL)

Installation

Prérequis

  • Windows (cible principale; Linux/macOS possible avec FPC/LCL)
  • Free Pascal Compiler (FPC) 3.2.2+
  • Lazarus IDE (optionnel, pour développement d'interface graphique)
  • Free Pascal Compiler (FPC) 3.2.2+ (pour le convertisseur tools/midi_to_tab.exe)

Construction depuis la Source

# Exécutable interface en ligne de commande
cd B:\dev\github\ChameleonDrummer
"%SystemDrive%\lazarus\fpc\3.2.2\bin\x86_64-win64\fpc.exe" -O2 -Fusrc -Sg -Sc ChameleonDrummer.lpr

# Exécutable interface graphique
cd gui
cmd /c "build_gui.bat < NUL"

Exécution de l'Exécutable

Les deux exécutables sont autonomes. Placez ChameleonDrummer.exe et chameleondrummer_gui.exe dans le même répertoire, ou référencez l'interface en ligne de commande depuis le répertoire de travail de l'interface graphique.

Concepts de Génération MIDI Batterie

Cette section explique les principes sous-jacents dérivés du code source (ComposerV2.pas, DrumGenerator.pas, Pattern.pas, Song.pas, MidiIO.pas).

1. Modèle Pattern et Pulsion (Pattern.pas)

Un TPattern est un conteneur d'objets TBeat. Chaque pulsation a :

  • Position (Double): Temps en pulsations (ex. 0.0, 0.5, 1.0). Position 1.0 = deuxième pulsation, position 2.0 = troisième pulsation, etc.
  • Instrument (TDrumInstrument): L'instrument de batterie (grosse caisse, caisse claire, hi-hat, etc.). L'identité de l'instrument vient d'un fichier JSON keymap — aucune note n'est hardcodée dans le code Pascal.
  • Vélocité (Integer): Vélocité MIDI de 0 (silence) à 127 (maximum). C'est ce qui fait que certains coups sonnent plus forts ou plus doux.
  • Durée (Double): Longueur de note en pulsations. La plupart des coups de batterie sont très courts (~0.1 pulsations), mais certains peuvent être plus longs pour l'effet.
  • GhostNote (Boolean): Note subtile, faible vélocité pour sensation groove. Pensez au batteur tapotant légèrement le bord d'un tambour entre les coups principaux.
  • Accent (Boolean): Coup accentué. C'est comment le batteur met l'accent sur certaines pulsations (comme la caisse claire sur temps 2 et 4 en rock).
  • InstrumentPromoted (Boolean): Drapeau provenance. Vrai seulement quand l'instrument de cette pulsation a été changé sur place par un plugin de genre promouvant un coup hi-hat existant vers un cymbale plus énergique pour section haute énergie.

2. Modèle Chanson et Section (Song.pas)

Un TSong contient sections (TSection), chacune avec ses propres patterns, fills, tempo, et mesure. Sections organisées en ordre standard: intro, verse, pre_chorus, chorus, bridge, breakdown, solo, outro.

Chaque section a ses propres :

  • Tempo — vitesse en pulsations par minute (BPM). 0 = hériter tempo chanson.
  • Mesure — signature temporelle (4/4, 7/8, 5/4, etc.). Premier nombre = pulsations par mesure, second = valeur note recevant une pulsation.
  • Complexité — variété des patterns. Utilisé seulement si HasComplexity défini; enregistrements zéro héritent complexité chanson.
  • Patterns par défaut — quels grooves/fills le moteur doit choisir pour cette section.

Sections stockées en fichiers JSON simples. Vous pouvez ajouter vos sections, changer l'ordre, ou donner à chaque section son propre tempo et mesure.

3. Évolution Pattern Mesure par Mesure (ComposerV2.pas)

TBarSelector.SelectPatternForPhrase choisit un groove par mesure via tirage aléatoire pondéré :

  • Correspondance intensité: Poids chaque groove basé sur adéquation sa bande intensité à intensité mesure. Grooves dont bande contient intensité mesure obtiennent bonus.
  • Pondération récence: Poids pattern précédent réduit à 0.25× pour retour possible mais rare répétition consécutive. Empêche même pattern mesure après mesure.
  • Phases macro: Chanson évolue en quatre phases :
    • mpEstablish (mesures initiales): essaie grooves légers pour établir feeling
    • mpMaintain (mesures moyennes): garde ce qui fonctionne
    • mpBuild (vers climax): favorise grooves plus lourds, intenses
    • mpTurnaround (fin): ramène au début ou chorus
  • Aléatoire thread-safe: Sélection utilise TThreadedRandom pour résultats cohérents entre threads.

4. Courbes d'Intensité (ComposerV2.pas)

Intensité varie sur chanson: intro/verse plus légers, chorus plus lourd, bridge/breakdown varient. Courbe intensité pilote sélection pattern et placement fills. Courbes typiques :

  • icAscending — plus fort vers climax
  • icDescending — commence fort, s'estompe
  • icPlateau — intensité ~constante
  • icDipRise — baisse puis monte (commun verse-chorus-verse)
  • icSteps — changements intensité distincts aux limites section

5. Macro Compositeur (ComposerV2.pas)

Phase macro biaise sélection pattern par section. Quatre phases (mpEstablish, mpMaintain, mpBuild, mpTurnaround) contrôlent évolution groove sur chanson, comme directeur musical disant "commence simple, construis énergie, puis ramène à la maison."

6. Moteur Groove (ComposerV2.pas)

Grooves chargés depuis fichiers config/grooves/.tab. Chaque bloc définit style/type/bande intensité. Moteur choisit groove meilleur ajustement par mesure.

Format bloc groove :

[style kind intensity=low-high]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.
  • Header: [style kind intensity=low-high]
  • style — ex. metal, rock, jazz, funk, electronic
  • kind — verse, chorus ou bridge
  • intensity=low-high — intensités mesure (0–1) que groove convient, ex. intensity=0.20-0.60
  • Ajouter mesure après type: [classic verse 7/8 intensity=0.2-0.7] pour grooves mesure impaire
  • Lignes instrument: Une ligne par instrument. Format: INSTRUMENT PAS PAS PAS | PAS PAS PAS
  • K = grosse caisse, S = caisse claire, RS = ride court, SS = splash, H = hi-hat, HO = hi-hat ouvert, HP = pédale hi-hat, R = tom rack, RB = tom basse, C = crash, C2 = second crash, CH = china, SP = splash, T1 = tom 1, T2 = tom 2, T3 = tom 3, T4 = tom 4
  • Caractères pas: . = silence (pas coup), x = coup, X = coup accentué, o = note douce, g = ghost note
  • Espaces dans mesure ignorés (améliorent lisibilité seulement)
  • Mesures séparées par |. Moteur utilise compte mesures ligne la plus longue; lignes plus courtes répètent leurs mesures.
  • Exemple (de rock.tab) :
[rock verse intensity=0.20-0.60]
K  x... .... x... .... | x... .... x... ..x.
S  .... x... .... x... | .... x... .... x...
H  x.x. x.x. x.x. x.x. | x.x. x.x. x.x. x.x.

7. Système Fills (ComposerV2.pas)

Fills chargés depuis config/fills/.tab. Chaque bloc définit nom/bande énergie. Moteur choisit fill dont énergie correspond intensité mesure aux limites section.

Format bloc fill :

[bonham_fill_short energy=0.3]
S ... ... ... xxx
  • Header: [name energy=0.3]
  • name — ex. bonham_fill_short, peart_fill_odd_7_8
  • energy=0.3 — intensité mesure (0–1) que fill convient le mieux
  • Même format instrument/pas que grooves: Mêmes caractères pas (., x, X, o, g), mêmes règles séparateur mesure/mesures.

8. Humanisation (AdvancedHumanization.pas)

Jitter timing et vélocité appliqués par note, échelonnés par réglage humanisation. Ghost notes et accents préservés.

  • Jitter timing: Chaque note décalée avant/arrière quelques ms. Assez petit pour sentir naturel, assez grand pour éviter effet "mitraillette".
  • Variation vélocité: Certains coups légèrement plus forts/doux qu'attendu.
  • Swing: Feeling où croches droites jouées avec léger ratio 2:1 ou 3:1, comme groove rock/funk classique. Contrôlé par flag interface en ligne de commande --swing ou curseur interface graphique (0 = droit, 0.67 = classique 2:1, 1 = 3:1).

Vous contrôlez tout avec curseur Humanisation interface graphique (0–1). À 0, parfait sur grille. À 1, feeling maximum.

9. Contraintes Physiques (PhysicalConstraints.pas / PatternFixer.pas)

Correcteur pattern élimine coups impossibles :

  • Max 3 coups sur un pas: Batteur ne peut frapper grosse caisse, caisse claire, et deux toms à la fois en un mouvement.
  • Patterns coordination membres :
    • Main droite: joue typiquement crash ou ride
    • Main gauche: hi-hat ou ride
    • Pied droit: pédale grosse caisse
    • Pied gauche: pédale hi-hat
  • Empêche moteur générer patterns qu'un vrai batteur ne pourrait jouer physiquement.

10. Architecture Plugins (PluginRegistry.pas, DrumGenerator.pas)

Plugins genre et batteur compilés dans l'exécutable. Chaque batteur applique 2–4 modifications :

  • BehindBeat: Batteur joue légèrement derrière temps pour feeling détendu.
  • GhostNotes: Ajoute rim-shots subtils et notes silencieuses.
  • LinearCoordination: Patterns membres typiques ce batteur (ex. patterns caractéristique grosse caisse-caisse claire Bonham).
  • ShuffleFeel: Feeling swing spécifique ce style.
  • FillPatterns: Vocabulaire fill typique ce batteur.

Modifications composables et appliquées dans ordre. Plugins genre (Metal, Rock, Jazz, Funk, Electronic) définissent bandes intensité typiques, quels grooves sens pour ce style, et structure chanson défaut.

11. Système Keymap (Kit.pas)

Notes MIDI résolues via fichiers JSON keymap dans mappings/. Aucune note hardcodée n'existe dans code Pascal.

  • Fichiers keymap mappent noms notes (kick, snare, hi-hat, tom1, crash, etc.) vers notes MIDI.
  • Même moteur génération peut utiliser n'importe quel keymap — GM, AD2, EZDrummer 3, Yamaha XG, ou utilisateur.
  • Vous pouvez éditer fichiers JSON keymap pour personnaliser quelle note déclenche quel tambour.

    • C'est pourquoi système fonctionne avec tant de librairies batterie différentes et pourquoi interface graphique n'hardcode pas noms tambours.

12. Export MIDI (MidiIO.pas, MidiParser.pas)

Écrivain SMF Format 0 brut avec encodage VLQ, événements méta tempo/mesure, compatible toutes DAWs et VSTs batterie.

  • Tracks : Une piste MIDI contenant toutes notes batterie.
  • Événements tempo : Changements BPM pendant progression chanson.
  • Événements mesure : Changements signature temporelle.
  • Données note : Hauteur (quel tambour), vélocité, temps début, durée.

Ce fichier MIDI fonctionne avec toute DAW (Reaper, Ardour, Ableton, Logic, etc.) et tout plugin VST batterie (EZDrummer, Superior Drummer, Addictive Drums, etc.).

Le Programme d'Interface Graphique

L'interface graphique (chameleondrummer_gui.exe) lie le moteur directement — produit exactement ce que l'outil ligne de commande produit, sans l'appeler.

  1. Lancez chameleondrummer_gui.exe.
  2. Choisissez genre, style, batteur, keymap, tempo, complexité, humanisation depuis interface.
  3. Cliquez Générer — fichier MIDI écrit.
  4. Optionnellement exportez projet REAPER (.rpp) ou session Ardour (.ardour) à côté.
  5. Dark mode disponible via Vue > Système/Clair/Sombre et persiste dans gui.ini.

L'interface graphique donne accès interactif à toutes options génération interface en ligne de commande plus retour visuel :

  • Aperçu temps réel combinaisons genre/style/batteur sélectionnées
  • Contrôles section dynamiques ajoutés runtime basés sur défauts genre
  • Support Dark mode (compilé seulement Windows)
  • Persistance configuration via gui.ini

Voir gui/README.md pour détails layout formulaire Lazarus, configuration composants, implémentation dark mode.

L'interface graphique inclut aussi bouton Step Editor ouvrant l'application standalone step editor (tools/step_editor/step_editor.exe). Le step editor permet éditer visuellement patterns batterie sur grille pas, convertir fichiers MIDI format tab, sauvegarder patterns comme grooves ou fills. Voir Step Editor pour détails.

Intégration REAPER

ChameleonDrummer s'intègre à REAPER via panneau Lua (reaper_chameleon/chameleon_panel.lua) pilotant interface en ligne de commande pour génération batterie et important résultats directement dans projet REAPER.

Installation

  1. Copiez répertoire reaper_chameleon/ dans dossier scripts REAPER.
  2. Ouvrez REAPER et chargez chameleon_panel.lua via Actions > Show action list > New > ReaScript.
  3. Panneau apparaît comme fenêtre ancrable avec quatre onglets.

Onglets

Song Sections

  • Sélectionnez genre, style, batteur, mapping, tempo, nombre mesures
  • Générez MIDI via interface en ligne de commande et importez dans projet REAPER actuel
  • Exportez projet REAPER (.rpp) à côté du MIDI

Additive Rhythm

  • Entrez notation groupement additif (ex. 3-3-3-3-2-2)
  • Définissez résolution grid (4, 8, 16, 32), tempo, batteur, intensité
  • Générez patterns rythme additif avec signatures temps par mesure
  • Export optionnel timeline JSON pour marqueurs tempo REAPER

Step Editor

  • Chargez item MIDI du projet actuel
  • Éditez sur grille avec application batteur (variance timing/vélocité)
  • Appliquez style batteur à patterns existants

Settings

  • Configurez chemin exécutable interface en ligne de commande
  • Définissez genre/style/batteur/mapping défaut
  • Actualisez options depuis commandes interface en ligne de commande list

Log

  • Sortie log temps réel commandes interface en ligne de commande
  • Messages statut pendant génération

Le Programme d'Interface en Ligne de Commande

Référence Commandes

Usage: chameleondrummer  [options]

Commands:
  generate         Generate a complete song (multi-bar pattern)
  pattern          Generate a single 1-4 bar pattern
  list             List available genres, styles, drummers, or mappings
  info             Show system information
  reaper           Create a REAPER project (sub-command: export)
  ardour           Create an Ardour session (sub-command: export)
  additive-rhythm  Generate additive rhythm patterns

Options:
  --genre               Genre (metal, rock, jazz, funk, electronic)
  --style               Style within genre (heavy, classic, swing, ...)
  --tempo                Tempo in BPM (default: genre/style value)
  --complexity <0-1>          Pattern complexity (default: 0.5)
  --humanization <0-1>        Humanization intensity (default: 0.3)
  --swing <0-1>               Swing feel: 0 = straight (default), 0.67 = classic 2:1, 1 = 3:1
  --time-sig             Meter of the song, e.g. 3/4, 5/4, 7/8, 9/8, 11/8, 13/8 (default 4/4)
  --strict-meter              Only use patterns matching --time-sig
  --segment   A section with its own tempo and meter, e.g. bridge:4:96:7/8
                              (bpm - keeps the song tempo); mix freely with --section
  --section     Song structure; repeat once per section, in order
                              e.g. --section intro:4 --section verse:8 --section chorus:8@140
                              (without --section the genre default structure is used)
  --drummer             Drummer style (e.g., bonham, peart, carey)
  --output              Output MIDI file path
  --reaper, --ardour          With generate: also write .rpp / the .ardour session
  --mapping             Keymap to use: gm (default), ad2, ezd3, xg
  --structure           Song structure from a JSON file (sections with bars, tempo,
                              complexity; optional genre, style, tempo). Command-line
                              genre/style/tempo win over the file. Not with --section.
  --sidecar             Same as --structure (the REAPER sidecar format works)
  --song-map            Read song map JSON for per-bar tempo/meter
  --write-timeline            Write timeline JSON after generation
  --list                List: genres, styles, drummers, mappings
  --json                      Output JSON for list commands
  --grouping             Additive grouping notation (e.g., 3-3-3-3-2-2)
  --grid                   Grid resolution for additive-rhythm (4, 8, 16, 32)
  --drummer-intensity <0-1>   Drummer intensity for additive-rhythm
  --help, -h                  Show this help

Exemples

Générer chanson complète :

ChameleonDrummer.exe generate --genre metal --style death --tempo 195 --drummer hoglan --mapping ad2 --output death_metal.mid

Générer pattern unique :

ChameleonDrummer.exe pattern --genre jazz --style swing --output swing_verse.mid

Créer projet REAPER :

ChameleonDrummer.exe reaper export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.rpp

Créer session Ardour :

ChameleonDrummer.exe ardour export --genre rock --style classic --drummer bonham --mapping gm --output rock_classic.ardour

Pattern rythme additif :

ChameleonDrummer.exe additive-rhythm --grouping "3-3-3-3-2-2" --grid 16 --tempo 120 --mapping gm --drummer bonham --drummer-intensity 0.8 --output additive.mid

Fonctionnalités Avancées

Song Maps et Sidecars

Sections (--section) : Décrit structure chanson directement ligne commande, un --section par section, ordre lecture :

ChameleonDrummer.exe generate --genre metal --style death --section intro:4 --section verse:8 --section chorus:8 --section bridge:4 --output song.mid

Sidecar (--sidecar) : Fichier JSON décrivant sections avec mesures, tempo, complexité, overrides optionnels genre/style/tempo. Genre/style/tempo ligne commande gagnent sur fichier.

Song Map (--song-map) : Fichier JSON décrivant changements tempo/mesure par mesure pour chansons progressives complexes.

Mesures Impaires

Moteur supporte mesures 2/4 à 32/16. Utilisez --time-sig n/d ou --segment pour spécifier. Grooves et fills chargés depuis fichiers .tab déclarant leur mesure dans header bloc (ex. [metal verse 7/8 intensity=0.40-0.90]).

Vos Propres Grooves, Fills et Defaults

Éditez fichiers dans config/ :

  • config/grooves/.tab — ajouter nouveaux grooves, changer bandes intensité
  • config/fills/.tab — ajouter nouveaux fills, changer niveaux énergie
  • config/defaults/.ini — changer tempo/style/batteur défaut
  • config/sections/.json — changer structure chanson défaut

Pas de recompilation nécessaire — moteur lit ces fichiers à l'exécution.

Ordre de Recherche

  1. Dossier dans variable environnement CHAMELEON_CONFIG, si défini
  2. %APPDATA%\ChameleonDrummer\config (Linux: ~/.config/ChameleonDrummer/config)
  3. config à côté du programme
  4. ..\config (builds développement)

Conversion MIDI → Tab

tools/midi_to_tab.exe convertit fichier MIDI en format groove/fill .tab. Compilé depuis Pascal, pas dépendances externes.

midi_to_tab.exe input.mid [output.tab]
midi_to_tab.exe input.mid --fill --name bonham_fill --energy 0.6
midi_to_tab.exe input.mid --meter 7/8 --resolution 16
midi_to_tab.exe input.mid --mapping mappings/gm.json --style rock --kind verse

Options

OptionDescription
--fillSortir bloc fill au lieu groove
--name Nom fill (défaut: fill)
--energy <0-1>Énergie fill (défaut: 0.5)
--meter Override mesure (défaut: méta MIDI ou 4/4)
--resolution Pas par croche: 4, 8, 16, 32 (défaut: 16)

Step Editor

Le Step Editor (tools/step_editor/step_editor.exe) est application graphique standalone pour éditer visuellement patterns batterie sur grille pas, convertir fichiers MIDI en format .tab groove/fill, et gérer blocs patterns dans fichiers config. Lancable depuis interface graphique principale via bouton Step Editor, ou exécutable directement.

Lancement Step Editor

  • Depuis interface graphique : Cliquez bouton Step Editor dans barre outils fenêtre principale.
  • Directement : Exécutez tools/step_editor/step_editor.exe depuis racine projet ou répertoire installation.
  • Depuis panneaux REAPER/Ardour : Onglet Step Editor dans panneaux intégration DAW lance éditeur avec item MIDI actuel chargé.

Fonctionnalités Principales

  • Édition Grille Pas : Grille visuelle 17 instruments batterie (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4) et pas configurables par mesure (4, 8, 16, 32, 64).
  • Caractères Vélocité/Articulation : Chaque pas utilise caractère: . (silence), x (normal), X (accent), o (doux/ghost), g (ghost). Cliquez cellules pour cycler états.
  • Conversion MIDI → Tab : Chargez fichier MIDI (.mid, .midi) et convertissez format tab via midi_to_tab.exe intégré avec mapping, style, type, intensité, énergie, résolution, mesure configurables.
  • Chargement Fichiers Tab : Chargez fichiers .tab existants (format config ChameleonDrummer et formats tab étrangers) pour édition.
  • Navigation Blocs (Fichiers Config) : Chargement fichier config depuis config/grooves/ ou config/fills/, éditeur parse tous blocs pattern et fournit sélecteur dropdown avec boutons Prev/Next navigation entre blocs.
  • Édition Blocs : Éditez champs header bloc (Style, Type, Intensité Low/High) directement UI. Changements marqués indicateur *.
  • Sauvegarde Chirurgicale : Sauvegardez blocs individuels vers fichier source sans affecter autres blocs même fichier.
  • Nouveaux/Supprimer Blocs : Ajoutez nouveaux blocs pattern vides ou supprimez existants (avec confirmation).
  • Zoom/Résolution : Changez résolution grille (8, 16, 32, 64 pas par mesure) et taille page.
  • Dark Mode : Détection auto thème système (Windows) avec override manuel. Tous contrôles y compris grille, combo boxes, barre état sont themed.
  • Auto-Scaling : Mise à l'échelle vectorielle proportionnelle tous éléments UI pour affichages high-DPI.
  • Export : Sauvegardez patterns édités comme nouveaux fichiers groove/fill .tab dans répertoires config.

Conversion MIDI → Tab

Sélection fichier MIDI (.mid, .midi), éditeur exécute auto midi_to_tab.exe avec réglages UI actuels et affiche résultat grille.

Paramètres Conversion (depuis UI) :

  • Mapping : Fichier JSON keymap (défaut: GM intégrée).
  • Style : Nom style groove (ex. metal, rock, jazz).
  • Kind : Type groove (verse, chorus, bridge, intro, outro, fill).
  • Intensity : Bande grooves (ex. 0.2-0.6).
  • Energy : Niveau fills (0.1–1.0).
  • Resolution : Pas par croche (4, 8, 16, 32).
  • Meter : Signature temps (ex. 4/4, 7/8, 4/4T feel triades).
  • Fill Mode : Activé = sort bloc fill au lieu groove.

Sortie brute conversion affichée log statut pour debug.

Formats Fichier Tab

Éditeur gère deux formats tab :

1. Format Config ChameleonDrummer (config/grooves/*.tab, config/fills/*.tab)

Multiples blocs pattern un fichier, chacun avec header :

[metal verse intensity=0.20-0.60]
K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...
|
K   x.x.x.x.x.x.x.x
...

[metal chorus intensity=0.40-0.80]
K   x.x.x.x.x.x.x.x
...

Chargement fichier config, éditeur :

  • Parse tous blocs et remplit sélecteur dropdown blocs.
  • Affiche UI navigation blocs (sélecteur, Prev/Next, champs header editables).
  • Permet sauvegarde chirurgicale blocs individuels sans réécrire tout fichier.

2. Format Tab Étranger (pattern unique, pas headers bloc)

Format simple lignes instruments seulement :

K   x.x.x.x.x.x.x.x
S   ..x...x...x...x.
HH  x.x.x.x.x.x.x.x
...

Chargés comme pattern unique editable sans navigation blocs.

Édition Grille Pas

  • Cliquez cellule pour cycler: . → x → X → o → g → .
  • Sélection plage : Glissez sélectionner plusieurs cellules. Utilisez Save Pattern As exporter région sélectionnée.
  • Abréviations instruments : Colonne gche fixe (K, S, RS, SS, H, HO, HP, R, RB, C, C2, CH, SP, T1, T2, T3, T4).
  • Numéros pas : Ligne haut affiche index pas dans chaque mesure.
  • Délimiteurs mesure : Lignes verticales plus épaisses marquent limites mesure.
  • Pages : Boutons Prev/Next Page ou dropdown Zoom naviguer patterns grands.

Gestion Blocs (Fichiers Config Seulement)

Fichier config chargé :

  • Sélecteur Bloc : Dropdown tous blocs format Style Kind (IntensityLow-IntensityHigh). Blocs modifiés suffixe *.
  • Prev/Next : Naviguer entre blocs.
  • Champs Header : Éditez Style, Kind, Intensity Low, Intensity High direct. Changements marquent bloc modifié.
  • Save Block : Écrit seulement bloc courant vers fichier source (sauvegarde chirurgicale).
  • New Block : Ajoute nouveau bloc vide (meter/résolution actuelle) au fichier.
  • Delete Block : Supprime bloc courant fichier (confirmation requise, garde au moins un bloc).

Sauvegarde Patterns

Save Pattern As : Exporte grille actuelle (ou région sélectionnée) nouveau fichier .tab dans config/grooves/
